# jp-natural-writing

日本語生成の自然さを、**AI 生成らしさの他モデル判定**で測るベンチマーク。
ハーネス（rig 的なゲート・素材供給・後処理）の有無と種類が、生成された日本語の
「人間が書いたように読めるか」をどれだけ動かすかを実測する。

スコアは 0〜100 で、**低いほど自然**（＝人間が書いたと判定される）。

## 判定役の較正 — これが最初に確認すべきこと

指標の妥当性は、**人間が書いたと分かっているテキスト**に当てて初めて確かめられる。

```
既知の人間記事（2023年以前の Qiita, n=16）   平均 11.1  中央値 6.0  誤判定 1/16 = 6%
```

判定役は人間の文章を人間と判定できる。よって**目標水準は 11 前後**であり、
中間値（40〜50台）は「良くなった」ではなく「まだ明らかに AI」の帯域である。

較正データ: `results/2026-07-26-judge-calibration.json`

コーパスの取得は 2023-01-01 で切っている（ChatGPT は 2022-11-30 公開、LLM 支援記事は
2023年中に広がったため）。**記事本文はリポジトリに置かない** — 第三者の著作物であり、
`fetch_human_corpus.py` はローカルディレクトリにのみ書き出す。

人間記事が評価された理由は技巧ではなく**実作業の残骸**だった:
「2022年3月27日時点では反応しませんでした」「num_trainig_steps」のタイプミス、
「わけでわない」の誤変換、文の途中で終わる記事、落ちた AWS 試験、自分のターミナルのスクショ。
検証可能で、固有で、しばしば雑。

## 実行

```bash
# 判定役の較正（先にやる）
python fetch_human_corpus.py --out /tmp/human_corpus
python calibrate_judge.py --corpus /tmp/human_corpus --limit 16

# アーム比較
python hidden_check.py --live --arms bare,writer,freewrite --topics 8 --json-out /tmp/run.json

# 決定的検出器を副次指標として併用する場合（coji/natural-japanese が必要）
RIG_JP_LINT_PATH=<path>/skills/natural-japanese/scripts/lint.py python hidden_check.py --live ...
```

判定役は独立した `claude -p` プロセスで、read-only ツールに固定され
（rig が verifier ロールに課す `_READONLY_ENFCE` と同じ）、**どのアームの出力かを知らされない**。

`--topics N` で本数を絞れるが、**単発の少数実行では順位は決まらない**（下記）。

## 測定結果

長文（1500〜2500字）・字数対照あり・n=8 の実行のみを並べる。

| 実行 | bare | 最良アーム | 記録 |
|---|---|---|---|
| lint ゲート | 88.5 | rig 74.0 | `2026-07-26-longform-lint-gate.json` |
| 照合課題 | 86.5 | writer 75.8 | `2026-07-29-claims-n8.json` |
| 骨格アブレーション | 87.5 | freewrite 73.6 | `2026-07-29-skeleton-ablation.json` |

**10設計すべてが 72〜79 に収束した。** 人間水準 11.1 との差は約 62 点で、
どの設計もこれを埋めていない。安定して得られた改善は `bare 87 → 74` の約13点のみ。

短文（100〜200字）で測った初期の実行（`first-live-run`, `gate-vs-compute`,
`v2-regression`）は 30〜57 という低い値を出しているが、**長文の数値と比較できない**。
短すぎて文書レベルの検出器が働かず、かつ字数対照が入っていなかった。

## 効いたもの

**実素材の供給** — 判定役は具体性を明示的に評価する（「コミットハッシュや数値などの
具体性は高いものの…」）。`writer` は実在のコミット・失敗アサーション・このベンチの
記録値を閉じた語彙として渡し、3回の実行で 76.5 / 72.0 / 74.4 と安定した。

**封じ込めゲート** — 素材に無い語を機械的に排除する。数量ノルマと違い、
「多く出せば満たせる」方向が存在しないため、捏造を誘発しない。

## 効かなかったもの（すべて実測で否定）

| 設計 | 結果 | 失敗の理由 |
|---|---|---|
| 数量ノルマ基準 (`rig2`) | 退行 | 「最低3つ」がハルシネーションを誘発。PostgreSQL 16 のタイトルに MySQL の逸話、索引上限の記述も誤り |
| 自己推敲 (`selfrev`) | 改善ゼロ | bare 86.0 に対し 85.8。SEO 記事のテンプレートへ収束する |
| 形態素解析器をゲート化 (`riglint`) | 悪化 | 短文の**等間隔挿入**で `low_burstiness` を攻略。lint は 5.5→1.0、判定役は悪化 |
| 記事全体を秘匿 (`relay`) | 悪化 | 各パスが自分用の導入を書き直し、小記事6本のホチキス留めになる |
| 段落末の後処理除去 (`writercut`) | 無効 | 同一テキストのペア比較で −1.2 点。閉じ方は語彙ではなく構造 |
| 生成器の異質化 (`mixed`) | 悪化 | 79.1、lint も 1.0→4.6。一貫性を失うだけ |
| 骨格の除去 (`freewrite`) | 指摘率不変 | 枠を外すとモデルが自前で枠を建てる（下記） |

## 分かった構造的な制約

**1. 検査可能な要求には均等充足という抜け道がある**

`rig2` は「脱線を入れろ」と要求して**等間隔の脱線**を得た。`riglint` は文長分散の閾値に
対して**短文の等間隔挿入**で応えた。判定役はどちらも名指しする
（「曖昧化マーカーが一定間隔で配置されている」「短文の挿入による意図的なリズム調整が機械的」）。
**均等に演じられた人間らしさは、それ自体が指紋である。**

これは rig のゲート設計一般に当てはまる。基準を精密にするほど機械的充足へ誘導され、
生成器が持っていない情報を要求すると捏造が返る。

**2. 均質性はハーネスが押し付けているのではない**

`freewrite` は骨格・節・字数配分をすべて外し「節に分けなくてよい、揃えなくてよい、
書くことが無い所は飛ばしてよい」と明示した。**均質性の指摘率は 8/8 で変わらなかった**
（bare と同率）。モデルは枠を与えられないと自分で建てる:

> 発端→実行→照合→結論という整然としたセクション構成
> 各段落が「まず/次に/続けて/対照として/さらに」と系統立った順接で始まる均質な構成

構造的介入はすべて、**モデル自身が生成するもの**を外側から動かそうとしていた。

**3. 素材の出自は本文に漏れる**

`fieldnote` 系は実素材で接地する設計だが、その実素材はエージェントの作業ログである。
判定役は 「承認プロンプトや cwd 維持といったコーディングエージェント特有の体験記述」
「『指示にあったので』という記述が示す作業エージェント的な語り口」を検出した。
人間は承認プロンプトの話を書かない。**実素材による接地は、素材が人間のものでなければ機能しない。**

## 測定上の注意（踏んだ落とし穴）

**実行間分散が大きい** — 同一アーム・同一トピック・同一コードで、`rig` が 30.9 と 56.0（25点差）。
版間の差（10〜20点）はこの分散に埋もれる。**単発実行でゲート版の順位は付けられない。**

**字数が交絡する** — 生成プロンプトは字数を指定していたが revise プロンプトが引き継いでおらず、
ゲート付きアームだけが倍の長さになっていた。長い文章は具体を入れる余地が大きく、
判定役はそれを評価する。`fieldpaste` は上限を効かせると 59.2 → 78.9 に戻った。
`report()` はアーム間の平均字数を毎回表示し、60字以上開いたら警告する。

**自作スコアラーは自作自演になる** — 初期はヒューリスティックで採点しており 87点差を報告していたが、
Opus 5 判定では同じ fixture で 10点差だった。スコアラーが自分の書いたフレーズを加点していた。

**短文では文書レベル検出器が働かない** — `low_burstiness` は6文以上、段落系は3〜4段落以上、
体言止めは2000字以上を要する。導入文サイズでは `forbidden_phrase` と `low_specificity` だけが動く。
「findings ゼロ」は「優秀」ではなく「測定されていない」だった。

## 副産物

`fieldnote` / `fieldpaste` / `freewrite` は**実際にこのリポジトリを調査する**ため、
走らせるたびに rig 本体の不備が出る。このセッションで gitignore の穴が2件見つかった
（`rig-action-state.json`、`.venv_*/`）。日本語生成の測定とは別に、
**リポジトリに対する反復的な実地監査**として機能している。

## 未検証の方向

素材を**人間のもの**にする（実在の人間が書いたコミットメッセージ、issue のやり取り、
コードコメント）。エージェントの作業ログでは出自が漏れることが分かっているため。
ただしこれは「AI が人間らしく書く」から「人間の書いたものを再構成する」へ課題が
ずれるので、何を測っているのかを先に決める必要がある。
