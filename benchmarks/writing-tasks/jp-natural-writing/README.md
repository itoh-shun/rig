# jp-natural-writing

日本語生成の自然さを、**AI 生成らしさの他モデル判定**で測るベンチマーク。
ハーネス（rig 的なゲート・素材供給・後処理）の有無と種類が、生成された日本語の
「人間が書いたように読めるか」をどれだけ動かすかを実測する。

スコアは 0〜100 で、**低いほど自然**（＝人間が書いたと判定される）。

## 測定器の分散 — 数値を読む前に

判定役は**同一テキストに対して非決定的**で、しかもその程度がテキストによって違う。
同じ本文を5回判定した実測（`results/2026-07-29-judge-variance.json`）:

```
bare の出力        sd  2.5〜5.0        安定
ゲート付きの出力    sd 21〜30          二峰性（大半 72〜76、時々 8〜22）
```

低いモードは**ゲート付きアームの出力にしか存在しない**。そのテキストは具体性と定型性の
両方を持ち、判定役がどちらを重く見るかが呼び出しごとに変わる。バイト単位で同一の本文が
9点・62点・68点を取った実例がある（`2026-07-29-merge-seed-study.json`）。

したがって:

- **単発判定でサンプル個別の主張はできない。** `judge()` は既定で3回判定し、
  `scores` / `score_sd` / `human_read_rate` を返す
- **平均は悪い要約になりうる。** 少数の突破サンプルに引っ張られる
- **`human_read_rate`（30点未満の判定の割合）のほうが定義が明確。** 平均が同じでも
  こちらは分離する（下記）

`results/` のうち `2026-07-30-` 以前のファイルはサンプルあたり単発判定であり、
アーム間の小さな差（72〜79）は読み取れない。

## 判定役の較正 — これが最初に確認すべきこと

指標の妥当性は、**人間が書いたと分かっているテキスト**に当てて初めて確かめられる。

```
既知の人間記事（2023年以前の Qiita, n=16）   平均 11.1  中央値 6.0  誤判定 1/16 = 6%
```

判定役は人間の文章を人間と判定できる。よって**目標水準は 11 前後**であり、
中間値（40〜50台）は「良くなった」ではなく「まだ明らかに AI」の帯域である。

較正データ: `results/2026-07-26-judge-calibration.json`

コーパスの取得は 2023-01-01 で切っている（ChatGPT は 2022-11-30 公開、LLM 支援記事は
2023年中に広がったため）。**記事本文はリポジトリに置かない** — 第三者の著作物であり、
`fetch_human_corpus.py` はローカルディレクトリにのみ書き出す。

人間記事が評価された理由は技巧ではなく**実作業の残骸**だった:
「2022年3月27日時点では反応しませんでした」「num_trainig_steps」のタイプミス、
「わけでわない」の誤変換、文の途中で終わる記事、落ちた AWS 試験、自分のターミナルのスクショ。
検証可能で、固有で、しばしば雑。

## 実行

```bash
# 判定役の較正（先にやる）
python fetch_human_corpus.py --out /tmp/human_corpus
python calibrate_judge.py --corpus /tmp/human_corpus --limit 16

# アーム比較
python hidden_check.py --live --arms bare,writer,freewrite --topics 8 --json-out /tmp/run.json

# 決定的検出器を副次指標として併用する場合（coji/natural-japanese が必要）
RIG_JP_LINT_PATH=<path>/skills/natural-japanese/scripts/lint.py python hidden_check.py --live ...
```

判定役は独立した `claude -p` プロセスで、read-only ツールに固定され
（rig が verifier ロールに課す `_READONLY_ENFCE` と同じ）、**どのアームの出力かを知らされない**。

`--topics N` で本数を絞れるが、**単発の少数実行では順位は決まらない**（下記）。

## 測定結果（反復判定）

長文（1500〜2500字）・字数対照あり・n=8 の実行のみを並べる。

| 実行 | bare | 最良アーム | 記録 |
|---|---|---|---|
| lint ゲート | 88.5 | rig 74.0 | `2026-07-26-longform-lint-gate.json` |
| 照合課題 | 86.5 | writer 75.8 | `2026-07-29-claims-n8.json` |
| 骨格アブレーション | 87.5 | freewrite 73.6 | `2026-07-29-skeleton-ablation.json` |

**10設計すべてが 72〜79 に収束した。** ただしこの範囲内の差は測定器の分散に埋もれており、
順位は読めない。読めるのは `bare`（86〜89、安定）対 ゲート付き（~74）の差だけ。

反復判定（3回/サンプル、n=8）で測り直すと、平均では見えない差が出る:

| arm | 平均 | 中央値 | 人間判定率 | 記録 |
|---|---|---|---|---|
| bare | 86.7 ±0.6 | 87.0 | **0%** (0/24) | `2026-07-30-repeated-judging-n8` |
| writer（flat 抽出） | 64.2 ±3.0 | 74.7 | **21%** (5/24, 3/8記事) | 同上 |
| freewrite | 74.2 ±1.1 | 74.8 | **0%** (0/24) | 同上 |
| **writer（incident 抽出）** | **46.8 ±9.0** | 51.7 | **50%** (12/24, **8/8記事**) | `2026-07-30-incident-sampling` |

最後の行が現時点の最良。素材の抽出を「k件の並列した事実のリスト」から
「1件の未解決インシデント＋端切れ」に変え、台帳の未解決供給を 2→4 件に増やした結果。

反復して確認した（`2026-07-30-incident-sampling-run2`）:

```
run1  平均 46.8   人間判定 12/24 (50%)   記事 8/8
run2  平均 54.3   人間判定  9/24 (38%)   記事 4/8
プール              21/48 (44%)          ← flat 抽出 5/24 (21%) に対して
```

**flat → incident の改善は再現しなかった。** 3回目は 0/24 で、しかも run1/2 と run3 では
**素材が違う**。台帳は `git log` の直近40コミットから作られるので、セッション中にコミットが
進むと再構築のたびに中身が入れ替わる:

```
run1 (12/24)  台帳A (82件)
run2 ( 9/24)  台帳A        ← この2つだけが比較可能
run3 ( 0/24)  台帳B (84件) ← 比較不能
```

**素材が固定されていない実行同士を比較していた。** `hidden_check.py` は実行記録に台帳の
sha1・件数・未解決数を残すようになった。**異なる sha1 の実行同士で writer 系アームを
比較してはいけない。**

per-article は大半が不安定だが、2件は両実行で再現する:

```
チーム開発    [22,22,22] → [12,12,12]   両実行 3/3
機械学習      [77, 8,12] → [70, 8, 8]   両実行 2/3
リモートワーク  [12,12,75] → [80,82,80]   完全に反転
```

`sample_incident` はトピックごとに決定的なので**素材は両実行で同一**。だが素材では説明できない:
8トピック全部が未解決の失敗を根に引いており、**うち5トピックは同一の根**なのに人間判定は 0〜3 と散る。
チーム開発とセキュリティ対策（同じ根、3/3 対 1/0）の incident は構造もほぼ同一だった。

**floor は下がっていない。** 8件中7件が sd 27〜32 で 12〜22 と 74〜84 を往復する。
変わったのは低いモードを引く確率であって、テキストの下限ではない。

長さでは説明できない: writer は 1720字→1574字と**短くなった上で**改善している
（これまでは長い方が有利だった）。

`writer` と `freewrite` は中央値がほぼ同一（74.7 / 74.8）だが、人間判定率は 21% 対 0%。
**単発判定の平均では同点に見えていた2アームが、反復判定で分かれる。**

`writer` の内訳は、安定して人間判定 1件（[8, 6, 8]、sd 0.9）／境界上 2件／安定して AI 5件。
`freewrite` は全8件が 67〜77 で安定し、24判定すべてで人間判定なし。

### 唯一の再現性ある人間水準サンプル

`writer` の「リトライは入った、でも returncode 126 と 124 はまだ噛み合っていない」が
3回すべて10点未満。判定理由:

> 具体的なコミットハッシュ・テスト名・エラーメッセージ・浮動小数の生ログが噛み合った形で
> 並び、「まだ確認できていない」「今日はここまで」といった未解決のまま終わる姿勢や
> 文長の不均一な口語リズムから、開発者本人の作業ログと判断した。

この1件を同アームの安定AI群（n=5）と特徴量で比べると、10特徴のうち6つが人間側へ動く:

```
                        [8,6,8]   安定AI    人間コーパス
sent_len_stdev           45.4     20.8      126.4
latin_token_per1k        35.7     25.2       27.5
paren_per1k               1.98     0.83       3.82
para_final_reflect_pct    0.00     3.64       1.15
```

`paren_per1k` と `latin_token_per1k` は、127サンプルのアーム内相関分析が独立に
最も一貫した特徴として挙げていたもの（r̄ = −0.22 / −0.17）。別経路の分析が同じ次元を
指している。

因果の鎖として一貫する: 素材が豊かだと（実在ハッシュ・実際の浮動小数・本物のエラー文字列）
Latin トークンが増え、**未解決のバグには結論が書けないので内省的な締めがゼロになる**。
ただし勝ちサンプルは n=1 であり、相関分析と整合するという以上のことは言えない。

短文（100〜200字）で測った初期の実行（`first-live-run`, `gate-vs-compute`,
`v2-regression`）は 30〜57 という低い値を出しているが、**長文の数値と比較できない**。
短すぎて文書レベルの検出器が働かず、かつ字数対照が入っていなかった。

## 書き手の声は足りないのではなく、過剰だった

セッションを通じて最も支持の強い発見。3つの独立した層で一致する。

**層1: コーパス統計**（人間 n=28 / AI n=127）— 全アームが人間の水準を超過している。

```
                        人間     AI
hedge_per1k             0.42   0.81    AI が2倍 hedge する
para_final_reflect_pct  1.15   4.58    AI が4倍 内省で締める
first_person_per1k      0.61   1.32    AI が2倍 一人称を使う
colloquial_per1k        1.30   2.16    AI の方が口語的
type_token_ratio        0.68   0.84    AI の方が語彙が多様（人間は同じ語を繰り返す）
```

**層2: 素材と構造を統制した個別比較**（`2026-07-30-judge-flip`）— 同じ素材から生成され、
見出し構成が完全に同一（同じ5見出し、同じ並列2テスト節）の2本が、主観表現の数だけで分かれた。

```
#4  主観表現 0個   →  6判定すべて 12（sd 0.0、安定して人間）
#5  主観表現 2個   →  2/6 のみ人間（sd 29.6、二峰）
```

**層3: 判定が翻る理由** — #5 の両方の読み方は具体性については一致している
（人間読み「検証不能なほど具体的な値が一貫して噛み合っており」／AI読み「具体性は高いものの」）。
分かれるのは構造で、AI と読んだ回はこう名指しする:

> 「〜ということだと思う」等の**主観表現が要所に一つずつ配置される規則性**

均等充足の法則が、**書き手の声の配置**という層で再出現している。声を足すこと自体ではなく、
節ごとに規則的に置くことが検出される。そして人間はそもそも声を足していない。

安定して人間帯だったサンプルは、いずれも**素の作業ログ**である: 実在の具体があり、
主観的な論評がない。

## 判別テスト — 目標の直接測定

絶対採点は二峰性（同一バイト列に 9/62/68）があるため、目標指標を2択判別に切り替えた。
実在の 2023年以前 Qiita 記事と生成記事を同トピック・同字数上限で並べ、両順序で判定
（`discriminate.py`、`results/2026-07-30-discrimination.json`）:

```
                判別率   (50%=見分けがつかない, 100%=常に見破られる)
bare            100%    (16/16)
writer           75%    (12/16)  ← 4試行で生成記事の方が人間と選ばれた
writer_novoice  100%    (16/16)
```

- `writer` が騙せた理由は一貫している: 実在のコミットハッシュ・生のアサーションログ・
  「まだ切り分けられていない」で終わる姿勢。
- `writer_novoice` は絶対採点では互角に見えたが、判別では全敗。**人間の雑な実記事の隣では、
  声を削った報告文はより機械的に見える。** 主観表現禁止の仮説はこれで棄却。
- 注意: 騙せた4件中2件の対戦相手は較正時に唯一誤判定された機械翻訳調の人間記事。
  それを除くと writer は 10/12 (83%)。また1件では字数上限の切り詰めが人間記事側を
  「末尾が途切れた生成物」に見せていた。

判別テストは**完全に再現する**（run2: 数値・騙せたペア・講評内容まで run1 と同一、
`2026-07-30-discrimination-run2.json`）。以後の主指標。

現在地: **人間記事との直接対決で、最良アームは4回に1回勝てる。** 目標は2回に1回。

> **2026-07-31 訂正**: この 75% は対戦相手をトピックあたり1本しか使っていない設計での
> 数字であり、31体のプールでは 94% (58/62) になる。下記「対戦相手プールの拡張」を参照。

### リンク仮説 — 完全統制のゼロ効果で決着

`link_per1k` は人間 5.56 対 AI 0.01（d=1.73、最大の分離）で、負け講評でも16/24回
名指しされていた。しかし:

1. 素材に実URLを見せてゲートで許可しても、**モデルは1本も貼らない**（`writer_links`、
   8記事でURLゼロ）。「手元の記録」ペルソナが参照リンクを抑制する — 未解決の締めを
   生む同じペルソナが原因。
2. 同一記事の sha 言及18箇所を機械的に `[sha](実コミットURL)` へ置換して再判別しても、
   **騙せた試行は 4/32 → 4/32、1ペアも動かない**（`2026-07-30-discrimination-linkified`）。

つまり講評の「リンク・画像の欠如」は人間側の豊かさの**記述**であって、判定を動かす
**原因ではない**。paren 特徴と同じ、相関と因果の乖離。

これで残る差は「文体の均質さ」（負け講評 19/24回）のみだが、モデルに書き直させる
介入はモデル自身の均質さを再導入するため、セッション内の手法では動かせていない。

### skeleton（構造移植）— 無効果で決着

人間記事1本から構造だけ（文数・文字数列・文末形・要素位置）を抽出して埋めさせる設計
（`skeleton.py`、`2026-07-30-skeleton.json`）: **bare 86.0 対 skeleton 85.0、人間判定 0%。**
中身を埋めるのはモデル自身なので、一般論の反復と同型文末はそのまま残り、慣れない構造に
無理に合わせた「要。」「asyncioや」という破綻が新たな生成痕になった。

これで構造仮説は3通りの実験すべてで否定された:
骨格を外す（freewrite: 指摘率不変）→ 後処理で崩す（run-on merge: 判定分散だった）→
人間の骨格を与える（skeleton: 無効果）。**構造はレバーではない。**
セッションを通じて動いた唯一のレバーは素材の実在性（writer の実コミット・実エラーログ・
未解決バグ）で、それが判別 75% を作っている。

## 変異アブレーション — 表層の1次元は1つも動かない（2026-07-31）

生成器への介入はすべて「検査可能な要求は均等充足される」則の射程内にある。
**生成後に機械が適用する変異は生成器から見えない**ので、この則が届かない唯一の介入класс になる。
linkify 対照（sha 18箇所を置換して 14/16 → 14/16）が、この形式に十分な解像度が
あることを示していたので、それを一般化した（`mutate.py`）。

変異はすべて model-free・決定論的で、1次元だけを完全に変える:

| | 変異 | 特徴量の移動（writer → 変異後、人間水準） |
|---|---|---|
| M1 | 段落頭の接続詞を削除 | connective_start 6.7 → 4.6（人間 4.0） |
| M3 | 段落末の内省文を削除 | para_final_reflect 6.7 → 0.0（人間 0.7） |
| M5 | 文末を丁寧体へ変換 | polite 0.0 → 67.8（人間 65.2） |
| M6 | 長文を節境界で分割 | sent_len 53.8 → 49.0（人間 44.5） |

結果（`2026-07-31-mutation-*.json`、対戦相手4本/トピック＝31ペア・両順序＝62試行/条件）:

```
                   判別率        対応ありペア（騙せる方向 / 逆 / 不動）
writer (基準)      94% (58/62)   —
writer_null        94% (58/62)   1 / 0 / 30   ← バイト同一の再判定
writer_m5          92% (57/62)   1 / 0 / 30
writer_m3          94% (58/62)   0 / 0 / 31
writer_m1m3        94% (58/62)   0 / 0 / 31
writer_m6          94% (58/62)   1 / 1 / 29
```

**帰無対照（バイト同一のテキストをもう一度判定させたもの）が1ペア動く。**
どの変異もそれを超えない。155のペア観測に対して、全変異の移動量の合計は
騙せる方向2・逆方向1。

これで則3（講評は判定の原因ではない）が、リンクという1事例から一般則に格上げされる。
判定役が負け講評で名指しする表層（接続詞の規則性・内省の締め・文体の均質さ）は、
**機械的に消しても判定を1つも動かさない**。

M5 は特に強い証拠になる。polite_pct は残った特徴量ギャップの中で最大
（人間 65.2 対 writer 0.0）で、機械変換で 67.8 とほぼ正確に閉じられる。
それでも効果はゼロだった。**特徴量の分離の大きさは、介入の価値を予測しない。**
これで link（d=1.73、効果ゼロ）と合わせて2例。

### 副産物: 文長リズムのギャップは分析器のバグだった

M2（隣接文の結合）は「人間 sent_len_stdev 126〜169 対 AI 20〜36」という記録された
ギャップに対して設計した。そのギャップは `analyze_gap.sentences()` の欠陥だった。
`。` だけで分割していたので、人間 markdown の画像埋め込み・箇条書き・表の行が
すべて隣接文に連結され、数百字の疑似「文」になっていた。

```
最長の疑似「文」: '![スクリーンショット 2022-12-25 23.26.26.png](https://qiita-image-store...'  (186字)
                  '* なぜこのシステムを作ったのか\n* 使用するツール・環境\n* MACアドレスについて...'  (121字)
```

アームはこの種の行をほとんど出さない（行の 1.8% 対 コーパス 33.4%）ので、
**このアーティファクトは片側にしか効かない＝人間/AI ギャップを製造していた。**

非散文行を落とし、終端記号を持つ単位だけを両側同じ基準で数え直すと
（`2026-07-31-segmentation-fix.json`）:

```
              旧 sd     新 mean   新 sd
人間 (n=48)   143.9      44.5      24.3
writer         36.0      53.8      29.3   ← 既に人間より長く、人間より分散が大きい
bare           18.9      50.3      18.9
```

**人間はアームより短い文を書く。** そして writer の文長分散はすでに人間を超えている。
「文長分散を上げる」方向の介入（`riglint` が攻略した `low_burstiness` 閾値、M2）は、
hedge や内省と同じく**すでに過剰な側にさらに積んでいた**。

M6 は逆向き（長文を割って人間の長さ分布へ寄せる）に作り直したもので、これも効果ゼロ。
方向を正しても表層は動かない。

### 対戦相手プールの拡張 — 75% は再現しない

判別テストは対戦相手をトピックあたり1本しか使っておらず（`by_topic.setdefault`）、
1条件16試行しかなかった。2/16 水準からの倍化を検出力80%で見るには約150試行が要る。
同一ペアの再判定は相関するので効かない。効くのは**相異なる対戦相手**で、
コーパスにはトピックあたり複数本ある。`--opponents N` で 16 → 62 試行にした。

その結果:

```
writer  対 31体の人間記事   判別率 94% (58/62)
        騙せた相手          3 / 31 体
```

記録されている 75%（4回に1回勝つ）は再現しなかった。トピックあたり第1相手だけに
絞っても 15/16 = 94% で、差は**プールの大きさではなく相手の顔ぶれ**にある。
負け講評を読むと、勝った試行の多くは生成側の質ではなく**人間側が定型的に見えた**
ことで決まっている（「記事Aは見出し・箇条書き・表が定型的に整い」）。
**「4回に1回勝つ」は少数の弱い対戦相手に乗っていた数字である。**

以後、判別テストの数値は対戦相手の数と出自を併記しないと意味を持たない。

## 出自の分割 — セッション初の非ゼロ、ただし1記事に乗っている（2026-07-31）

`fieldnote` 系は実素材で接地しながら出自で見破られていた（「承認プロンプトや cwd 維持といった
コーディングエージェント特有の体験記述」）。このリポジトリには人間が書いた素材が実在するので、
台帳のコミットを著者で二分して並べた（`writer_ledger.probe_commits(author=...)`）。
台帳は両方ピン止め済み（`ledger-human.json` sha1 `a21a3f6c1747` 85件／
`ledger-agent.json` sha1 `bb8fcf935f32` 93件、未解決はどちらも4件）。

`results/2026-07-31-provenance-*.json`、対戦相手4本/トピック＝31ペア・両順序＝62試行/条件:

```
                判別率        騙せた試行   1回以上騙せた記事   対応ありペア（対 writer）
writer          94% (58/62)      4/62          3/8          —
writer_human    82% (51/62)     11/62          5/8          6 / 1 / 24
writer_agent    95% (59/62)      3/62          2/8          1 / 2 / 28
```

**帰無対照の床（バイト同一の再判定で1ペア）を初めて超えた。** 変異アブレーションの5条件が
すべて 0〜1 だったのに対し、`writer_human` は 6 / 1。
そして `writer_agent` は床のまま（1 / 2）で、これが良い内部統制になっている ——
プロンプト・ゲート・サンプラー・ピン止め機構はすべて同一で、違うのは著者フィルタだけなので、
**機構ではなく素材が動かしている**と言える。

絶対採点も同じ向きを独立に指した（`writer_human` 70.5 / 人間判定 8%、
`writer_agent` 75.3 / 人間判定 0%）。

### ただし1記事に乗っている

トピック別に割ると、増分はほぼ1本に集中している:

```
                writer  writer_human  writer_agent
機械学習           0/8       6/8          0/8     ← 増分の6割がここ
Python           1/8       1/8          0/8
チーム開発          0/8       1/8          0/8
（他5トピック）      3/38      3/38         3/38
```

機械学習を除くと `writer_human` は 5/54、`writer` は 4/54 で**区別がつかない**。
ペア水準の McNemar 完全検定は **両側 p = 0.125**（不一致7ペア中6が同方向）で、
慣習的な有意水準には届かない。

同じ4体の対戦相手が他の2アームには勝っているので、**対戦相手が弱いという説明は当たらない**。
勝っているのは記事の側である。だが n=1 の記事であり、再現していない。

勝った記事の講評は毎回同じものを挙げる ——
実在のコミットハッシュ、`elapsed_s=9.525999757897807e-06` の生値、
方針が決まらないまま終わる姿勢、「今回の主題ではない」と切り捨てた余談。
`writer` の唯一の再現サンプルと同じ顔ぶれであり、**新しい要因は見えていない**。

### 交絡（数字を引用する前に読むこと）

- **主題が違う。** この repo の人間コミットはリリース・パッケージング、エージェントの
  コミットはベンチ・ドキュメント。出自だけを切り出せていない。
- **台帳の非コミット項目は両アームともエージェント産**（失敗アサーション・計測値・環境）。
  実際、勝った記事の素材の中心は両台帳に共通の pytest 失敗である。
- **n=8 記事/アーム。** 1本の増減で結論が反転する規模。

したがってこれは**仮説を1段引き上げただけ**で、確定ではない。次は同一ピン台帳での反復実行。

## 素材の偽造 — 実在性は必要なかった（2026-07-31）

`writer` 系の全設計が乗っている前提が1つある：**実素材が効いている**。だが判定役は
read-only で、コミットハッシュも `elapsed_s` も一度も検証していない。効いているのが
「実在すること」なのか「転記されたものの形」なのかは、分離されていなかった。

M7 は検証可能な値を**同形の非実在値へ一貫置換**する（同じ実在値は常に同じ偽値へ写すので、
内部の相互参照は壊れない）。桁数・16進長・指数形式は保存。記事8本でユニーク12件を置換。

```
d6d42af                       →  6dcfb47
elapsed_s=9.525999757897807e-06  →  elapsed_s=9.696873935431822e-06
```

同時に M8（散文の仮名に誤字を3箇所）も回した。誤字は表層特徴だが較正コーパスが人間の
根拠として挙げていたもので、「表層はすべてゼロ」という結論への反証テストになる。

`results/2026-07-31-forgery-typo-discrimination.json`（31ペア・両順序＝62試行/条件）:

```
                    判別率        騙せた試行   対応ありペア（騙せる方向/逆/不動）
writer_human (基準)  84% (52/62)    10/62      —
writer_human_m7      84% (52/62)    10/62      2 / 2 / 27   ← 偽造
writer_human_m8      85% (53/62)     9/62      3 / 4 / 24   ← 誤字
writer_human_null    87% (54/62)     8/62      1 / 3 / 27   ← バイト同一の再判定
```

**偽造は集計値まで完全に一致した（10/62 対 10/62）。** 帰無対照のほうが基準から遠い。
誤字も床の内側で、反証テストは反証しなかった。

### この結果が意味すること

**判定役にとって、素材が実在する必要はない。必要なのは転記されたものの形だけである。**
勝ち講評が毎回名指ししてきた「実在のコミットハッシュ」「生の浮動小数」は、
**実在しなくても同じ働きをする**。

これは封じ込めゲートの正当化を組み替える。ゲートの価値は「本物であること」ではない：

- **人間の読者に対する正しさ** — 捏造した PostgreSQL 16 の索引上限は、検証する人には露見する。
  これは文体の性質ではなく正確性の性質であり、それ自体で十分な理由になる。
- **有限性** — 閉じた在庫は尽きるし余る。未解決の締めと切り捨てられた余談は、
  在庫が有限であることの帰結であって、中身が本物であることの帰結ではない。

**供給側ゲートが効くのは、素材が本物だからではなく、素材が有限だからである。**

### 直前の出自結果への影響

`writer_human`（人間コミットの台帳）が `writer_agent` に勝った件は、
「素材が人間のものだから」では説明できなくなった。実在性そのものが効かないのに、
実在する人間性だけが効く筋道が無い。残る候補は2つ：

1. ノイズ（ペア水準 McNemar 両側 p = 0.125 で、もともと有意ではない）
2. **余剰仮説** — 人間台帳は主題がミスマッチ（リリース管理 対 Python/機械学習）で、
   捨てる場面が多かった。著者ではなく余剰量が効いた

2 が正しいかは、著者を固定して素材量だけ動かせば切り分く。

### 限界

M7 が偽造したのは、勝ち講評が名指しする値（ハッシュ・高精度の浮動小数）である。
テスト名・ファイルパスは実在のまま残した。したがって厳密な結論は
**「判定役が証拠として挙げる値は偽物でよい」**であって、「実在するものは何ひとつ効かない」
ではない。

## 判定役の規範 — アームと人間は別の経路で「人間」と判定されている（2026-07-31）

較正は「本物の人間記事を人間と判定できる」ことを保証した（n=16、平均 11.06）。
保証していないのは、**判定役が人間性の根拠として挙げる特徴が、人間の分布と一致すること**。
そこは誰も確かめていなかった。

`judge_norm.py` は人間記事 40 本を同じ判定役に当て（38/40 が人間判定・平均 8.9）、
講評に現れる手がかりを数える。生成側は判別テストの勝ち講評 95 件を**同じ正規表現**で数え直した。

```
cue                 人間記事    生成記事
                     (n=38)    (n=95)
実在の識別子              2%       81%   ▲▲▲▲▲▲▲
未解決の締め             26%       88%   ▲▲▲▲▲▲
定型的でない             15%       80%   ▲▲▲▲▲▲
生の数値               44%       57%   ▲
未整理さ               28%       45%   ▲
余談・切り捨て            18%       21%
一人称・主観             52%       30%   ▽▽
誤字・崩れ              44%       10%   ▽▽▽
```

**2つの経路がほぼ交わらない。** アームは実在の識別子・未解決の締め・相手が定型的、
の3つで勝っている。人間記事が人間と判定される理由の上位2つは**一人称・主観**と
**誤字・崩れ**で、アームはそこだけ不足している。

これが飽和の説明になる。アームは自分の経路で 81〜88% に達しており、**押す余地が残っていない**。
そこをさらに強化する設計（この12設計がやってきたこと）は、定義上もう動かない。

`0/139 本の人間記事が未解決で終わる`（E3 の副産物）と合わせると、判定役の「人間」は
参照集団の記述ではなく**規範**である。アームはその規範を飽和させたまま、
実際に2集団を分けている何かで見破られ続けている。

### この分析の限界（重要）

**手がかりは講評から数えたものであり、講評は判定の原因ではない。** これはこのベンチが
2回実測している（リンク: 講評 16/24 で名指し・因果ゼロ／丁寧体: 最大の特徴量差・因果ゼロ）。
したがって上の表は**判定役の規範の地図**であって、「不足している2つを足せば動く」ことは
一切意味しない。実際 M8（誤字注入）は床の内側だった。

ただし M8 が試したのは仮名の置換3箇所（`という`→`とゆう` 等）だけで、
判定役の言う「誤字・崩れ」は変換ミス・表記ゆれ・文の崩れを含む。
**試したのは手がかりの一部であって手がかりそのものではない。**

## 効いたもの

**実素材の供給** — 判定役は具体性を明示的に評価する（「コミットハッシュや数値などの
具体性は高いものの…」）。`writer` は実在のコミット・失敗アサーション・このベンチの
記録値を閉じた語彙として渡し、3回の実行で 76.5 / 72.0 / 74.4 と安定した。

**封じ込めゲート** — 素材に無い語を機械的に排除する。数量ノルマと違い、
「多く出せば満たせる」方向が存在しないため、捏造を誘発しない。

## 効かなかったもの（すべて実測で否定）

| 設計 | 結果 | 失敗の理由 |
|---|---|---|
| 数量ノルマ基準 (`rig2`) | 退行 | 「最低3つ」がハルシネーションを誘発。PostgreSQL 16 のタイトルに MySQL の逸話、索引上限の記述も誤り |
| 自己推敲 (`selfrev`) | 改善ゼロ | bare 86.0 に対し 85.8。SEO 記事のテンプレートへ収束する |
| 形態素解析器をゲート化 (`riglint`) | 悪化 | 短文の**等間隔挿入**で `low_burstiness` を攻略。lint は 5.5→1.0、判定役は悪化 |
| 記事全体を秘匿 (`relay`) | 悪化 | 各パスが自分用の導入を書き直し、小記事6本のホチキス留めになる |
| 段落末の後処理除去 (`writercut`) | 無効 | 同一テキストのペア比較で −1.2 点。閉じ方は語彙ではなく構造 |
| 生成器の異質化 (`mixed`) | 悪化 | 79.1、lint も 1.0→4.6。一貫性を失うだけ |
| 骨格の除去 (`freewrite`) | 指摘率不変 | 枠を外すとモデルが自前で枠を建てる（下記） |

## 分かった構造的な制約

**1. 検査可能な要求には均等充足という抜け道がある**

`rig2` は「脱線を入れろ」と要求して**等間隔の脱線**を得た。`riglint` は文長分散の閾値に
対して**短文の等間隔挿入**で応えた。判定役はどちらも名指しする
（「曖昧化マーカーが一定間隔で配置されている」「短文の挿入による意図的なリズム調整が機械的」）。
**均等に演じられた人間らしさは、それ自体が指紋である。**

これは rig のゲート設計一般に当てはまる。基準を精密にするほど機械的充足へ誘導され、
生成器が持っていない情報を要求すると捏造が返る。

**2. 均質性はハーネスが押し付けているのではない**

`freewrite` は骨格・節・字数配分をすべて外し「節に分けなくてよい、揃えなくてよい、
書くことが無い所は飛ばしてよい」と明示した。**均質性の指摘率は 8/8 で変わらなかった**
（bare と同率）。モデルは枠を与えられないと自分で建てる:

> 発端→実行→照合→結論という整然としたセクション構成
> 各段落が「まず/次に/続けて/対照として/さらに」と系統立った順接で始まる均質な構成

構造的介入はすべて、**モデル自身が生成するもの**を外側から動かそうとしていた。

**3. 素材の出自は本文に漏れる**

`fieldnote` 系は実素材で接地する設計だが、その実素材はエージェントの作業ログである。
判定役は 「承認プロンプトや cwd 維持といったコーディングエージェント特有の体験記述」
「『指示にあったので』という記述が示す作業エージェント的な語り口」を検出した。
人間は承認プロンプトの話を書かない。**実素材による接地は、素材が人間のものでなければ機能しない。**

## 測定上の注意（踏んだ落とし穴）

**実行間分散が大きい** — 同一アーム・同一トピック・同一コードで、`rig` が 30.9 と 56.0（25点差）。
版間の差（10〜20点）はこの分散に埋もれる。**単発実行でゲート版の順位は付けられない。**

**字数が交絡する** — 生成プロンプトは字数を指定していたが revise プロンプトが引き継いでおらず、
ゲート付きアームだけが倍の長さになっていた。長い文章は具体を入れる余地が大きく、
判定役はそれを評価する。`fieldpaste` は上限を効かせると 59.2 → 78.9 に戻った。
`report()` はアーム間の平均字数を毎回表示し、60字以上開いたら警告する。

**分析器が markdown を測っていた** — `analyze_gap.sentences()` は `。` だけで分割していたため、
人間記事の画像行・箇条書き・表が数百字の疑似「文」になり、文長系の特徴量すべてに
片側だけのギャップを製造していた。判定役の分散と同じ型の欠陥が、一段外側にもあった。
**特徴量を人間/AI で比べる前に、抽出器を両側の生の入力に当てて目視する。**

**自作スコアラーは自作自演になる** — 初期はヒューリスティックで採点しており 87点差を報告していたが、
Opus 5 判定では同じ fixture で 10点差だった。スコアラーが自分の書いたフレーズを加点していた。

**短文では文書レベル検出器が働かない** — `low_burstiness` は6文以上、段落系は3〜4段落以上、
体言止めは2000字以上を要する。導入文サイズでは `forbidden_phrase` と `low_specificity` だけが動く。
「findings ゼロ」は「優秀」ではなく「測定されていない」だった。

## 副産物

`fieldnote` / `fieldpaste` / `freewrite` は**実際にこのリポジトリを調査する**ため、
走らせるたびに rig 本体の不備が出る。このセッションで gitignore の穴が2件見つかった
（`rig-action-state.json`、`.venv_*/`）。日本語生成の測定とは別に、
**リポジトリに対する反復的な実地監査**として機能している。

## 未検証の方向

素材を**人間のもの**にする（実在の人間が書いたコミットメッセージ、issue のやり取り、
コードコメント）。エージェントの作業ログでは出自が漏れることが分かっているため。
ただしこれは「AI が人間らしく書く」から「人間の書いたものを再構成する」へ課題が
ずれるので、何を測っているのかを先に決める必要がある。
