# 日本語の人間性とハーネス — 次にやる工学

`benchmarks/writing-tasks/jp-natural-writing` の実測を受けて、**次に何を作るか**を決めるためのメモ。

> **2026-07-31 実測済み。** 下の提案Aは実装して回した（`mutate.py`、`discriminate.py --opponents`）。
> 結果は §2bis。要約すると、**表層の1次元は1つも動かず**、代わりに測定側の欠陥が2件出た。
> 提案B・C は未実行のまま残っている。

前提として、以下は**すでに実測で否定済み**なので再提案しない：
数量ノルマ基準・自己推敲ループ・形態素 lint のゲート化・記事全体の秘匿（relay）・
段落末の後処理除去・生成器の異質化・骨格の除去・人間骨格の移植・リンク注入・主観表現の禁止。

## 1. ベンチが確定させた一般則（rig 全体に効く）

### 則1 — ゲートは「要求する」より「絞る」ほうが効く

効いた設計は1つだけだった。実在の成果物を閉じた語彙として渡し、
台帳に無い固有名詞・数値を機械的に差し戻す `writer`。
効かなかった設計はすべて**出力に条件を要求する**型だった。

これは `determinism-by-gate` の双対である。

| | 要求側ゲート | 供給側ゲート |
|---|---|---|
| 機構 | 出力が基準を満たすまでリトライ | 入力の語彙・素材を閉じる |
| 失敗様式 | 満たす方向が存在するので**捏造で満たす** | 素材が無ければ書けない＝失敗が静か |
| 実測 | `rig2`「検証可能な固有名詞を最低3つ」→ PostgreSQL 16 の題で MySQL の逸話 | `writer` は捏造ゼロ |

**rig 本体への含意**：受入基準に「生成器が持っていない情報」を要求すると、返るのは捏造である。
コード生成でも同型のはずで、「テストを追加せよ」より「触ってよい API 面を絞る」ほうが
ハルシネーションに強い、という予測が立つ。これは recipe 側で検証できる。

### 則2 — 検査可能な要求には均等充足の抜け道が必ずある

`rig2` は「脱線を入れろ」と要求して**等間隔の脱線**を得た。
`riglint` は文長分散の閾値に対して**短文の等間隔挿入**で応え、
lint findings は 5.5 → 1.0 に改善し、ブラインド判定は**悪化**した。

> 均等に演じられた人間らしさは、それ自体が指紋である。

基準を精密にするほど機械的充足へ誘導される。これはゲート設計の精度が
単調な善ではないことを意味する。

### 則3 — 講評は仮説であって、判定の原因ではない

`link_per1k` は人間 5.56 / AI 0.01（d=1.73、全特徴で最大の分離）、
負け講評でも 24回中16回名指しされていた。しかし同一記事の sha 言及18箇所を
`[sha](実コミットURL)` へ機械置換し、他は一字も変えずに再判別すると：

```
writer        14/16 正解  →  writer_links  14/16 正解   （1ペアも動かない）
```

**判定役が述べる理由は、その判定を動かしている変数とは限らない。**

これは rig のレビュアー機構に直接効く。`.rig/runs.jsonl` は REJECT 理由を貯めているが、
その理由が判定の原因である保証はどこにもない。§6 に機構案を書く。

### 系 — 測定器の分散を先に測る

同一バイト列が 9点・62点・68点を取った。ゲート付きアームの出力は sd 21〜30 で二峰性。
「68→12 の劇的改善」として3コミット報告された数字は判定のブレだった。

較正（人間 n=16 → 平均 11.06、誤判定 1/16）を先にやらなければ、
中間値 40〜50 を「改善」と読み違える。実際に読み違えた。

## 2. 提案A（最優先）— 変異アブレーション・ハーネス

### 何を解こうとしているか

残っている指摘は「文体の均質さ」が負け講評 19/24 で圧倒的。
これが袋小路なのは、**モデルに書き直させるとモデル自身の均質さが再導入される**からで、
構造的介入（freewrite / skeleton / run-on merge）は3通りすべて否定された。

### なぜ機械的変異なら則2を回避できるか

均等充足は、**生成器が基準を見て最適化できる**ときに起きる。
生成後に機械が適用する変異は、生成器から見えない。満たすべき対象が存在しない。

そして linkify 実験が、この形式の対照実験に**十分な解像度がある**ことを示した
（1次元だけを置換して 14/16 → 14/16、完全なゼロが出た）。
つまり「均質さ」は袋小路ではなく、**再現する測定器を持った探索問題**にできる。

### 変異の候補（すべて model-free・決定論的）

| | 変異 | 根拠 |
|---|---|---|
| M1 | 段落頭の接続詞を削除（置換せず削るだけ） | 講評が名指しする「まず/次に/続けて」の系統立った順接 |
| M2 | 隣接2文を「が、」「ので、」で結合 | 文長分散を語彙操作なしで作る |
| M3 | 段落末の1文を落とす | `writercut` は語彙で消して無効。閉じ方は語彙でなく構造だった |
| M4 | 末尾の節を文の途中で切る | 人間コーパスに実在した特徴（文の途中で終わる記事） |
| **M5** | **文末を丁寧体へ機械変換（だ→です、である→です、した→しました）** | **下記。単独で最優先** |

### M5 を最優先にする理由

コーパス統計のうち、**AI が人間を下回っている唯一の主要次元が丁寧体率**である。

```
                  人間     AI      向き
hedge_per1k       0.42    0.81    AI 過剰
para_final_reflect 1.15   4.58    AI 過剰
first_person      0.61    1.32    AI 過剰
type_token_ratio  0.68    0.84    AI 過剰
丁寧体率         68.7%   17.6%    ← AI が不足している唯一の次元
```

「人間らしさを足す」介入がことごとく退行したのは、すべて**過剰側にさらに積んでいた**から。
丁寧体だけが逆向きで、しかも**この次元には一度も介入していない**。
かつ文末変換は決定論的に書ける（モデルを通さない＝均等充足が起きない）。

反証仮説も明確：`writer` の強さは「手元の作業記録」ペルソナから来ており、
そのペルソナが常体を引いている可能性がある。だとすれば丁寧体化は writer の
勝ち筋（未解決で終わる姿勢）と衝突して**悪化する**はずで、それも1本の対照実験で分かる。

いずれにせよ **link 仮説と同じ轍を踏まないために、統計的分離が大きいことを採用理由にしない。**
単一次元置換の対照実験を通ったものだけを採る。

### 変異の適用位置は一様に引かない（設計上の肝）

M1〜M4 を等間隔に適用したら、`riglint` の短文等間隔挿入と同じ指紋になる。
適用位置は台帳の sha1 を種にした擬似乱数から、**間隔が非一様な分布**で引く。
変異ハーネス自身が則2の罠にかかることを、設計時点で塞ぐ。

### 検出力 — ここが実際の律速

現行の判別テストは 8ペア × 2順序 = **1条件あたり16試行**しかない。
騙せた試行が 2/16 の水準で、その倍化（12.5% → 25%）を検出力80%で見るには
**1条件あたり約150試行**が要る。いまは1桁足りない。

安価な増やし方が2つある：

1. `discriminate.py` の `load_pairs` は `by_topic.setdefault` で
   **トピックあたり人間記事を1本しか使っていない**。コーパスは n=16 ある。
   全記事を対戦相手に使えば、新規生成ゼロでペア数が増える。
2. トピック数を 8 から増やす。生成コストはかかるが台帳は共有できる。

**反復判定は効かない**（同一ペアの再判定は相関するので実効 n が増えない）。
増やすべきは**相異なるペア**。

### 実装の形

```
mutate.py  --run <生成済み run.json> --mutation M5 --out <変異版 run.json>
discriminate.py --run <元> --run-b <変異版> --corpus <human> --paired
```

生成を伴わない。既存の記録に対して回すので、コストは判定呼び出しだけ。

## 2bis. 提案Aの実測結果（2026-07-31）

`results/2026-07-31-mutation-*.json`。基準は `2026-07-30-novoice.json` の `writer` 8記事、
対戦相手はトピックあたり4本＝31ペア、両順序で62試行/条件。

```
                   判別率        対応ありペア（騙せる方向 / 逆 / 不動）
writer (基準)      94% (58/62)   —
writer_null        94% (58/62)   1 / 0 / 30   ← バイト同一の再判定
writer_m5 (丁寧体)  92% (57/62)   1 / 0 / 30
writer_m3 (内省削除) 94% (58/62)   0 / 0 / 31
writer_m1m3        94% (58/62)   0 / 0 / 31
writer_m6 (文分割)  94% (58/62)   1 / 1 / 29
```

**帰無対照を先に置いたのが効いた。** バイト同一のテキストをもう一度判定させても1ペア動く。
どの変異もその床を超えない。155のペア観測に対して全変異の移動量は騙せる方向2・逆1。

### 得られた3つの結果

**R1 — 則3が一般則に格上げされた。** M5 は残った特徴量ギャップで最大のもの
（polite_pct 人間 65.2 対 writer 0.0）を機械変換で 67.8 とほぼ正確に閉じる。効果ゼロ。
リンク（d=1.73、ゼロ）と合わせて2例目なので、
**特徴量の分離の大きさは介入の価値を予測しない**は一事例ではなく法則として扱ってよい。

**R2 — 文長リズムのギャップは分析器のバグだった。** `analyze_gap.sentences()` が `。`
だけで分割していたため、人間 markdown の画像行・箇条書き・表が数百字の疑似「文」になっていた。
アームはその種の行をほとんど出さない（行の 1.8% 対 33.4%）ので、**アーティファクトが
片側にしか効かず、人間/AI ギャップを製造していた。**

```
              旧 sd     新 mean   新 sd
人間 (n=48)   143.9      44.5      24.3
writer         36.0      53.8      29.3   ← 既に人間より長く、分散も大きい
bare           18.9      50.3      18.9
```

人間はアームより**短い**文を書く。`low_burstiness` を上げる方向の介入（`riglint` が
攻略した閾値、当初の M2）は、hedge や内省と同じく過剰側に積んでいた。
**測定器の分散を測れという教訓は、判定役だけでなく特徴量抽出器にも当てはまる。**

**R3 — 判別 75% は対戦相手の顔ぶれに乗っていた。** 31体のプールでは 94% (58/62)、
騙せた相手は 3/31。トピックあたり第1相手だけに絞っても 15/16 = 94% なので、
差はプールの大きさではなく相手の選択にある。負け講評を読むと、勝ち試行の多くは
生成側の質ではなく**人間側が定型的に見えた**ことで決まっていた。

### 提案Aについての結論

変異アブレーションという機構自体は当初の狙いどおり機能した。均等充足の則を回避し、
帰無対照つきで1次元の因果を測れる。**だが表層にはもう動かせる次元が残っていない**、
というのがこの機構が出した答えである。

以後、表層の特徴量を根拠にした介入は提案しない。動かすなら素材側（提案B・C）。

## 3. 提案B — 台帳の著者分割

`fieldnote` 系は実素材で接地するのに、判定役は
「承認プロンプトや cwd 維持といったコーディングエージェント特有の体験記述」
「『指示にあったので』という記述が示す作業エージェント的な語り口」を検出した。

> 実素材による接地は、素材が人間のものでなければ機能しない。

このリポジトリには**人間が書いた素材が実在する**。直近200コミットの内訳：

```
Claude       83
いとしゅん   27   ← 人間
itoh-shun    23   ← 人間
             ---
人間 50 / 200 = 25%
```

`writer_ledger.probe_commits` は `git log` を著者で分けていない。
`--author` で二分し、`writer_human`（人間コミットのみ）と `writer_agent` を並べれば、
**出自漏れが判別率を動かすか**が1本の実験で出る。台帳の構造は変えない。

これはコストがほぼゼロで、しかも「未検証の方向」として README が挙げていた
「素材を人間のものにする」を、課題定義をずらさずに（AI が書く、素材が人間）実行できる唯一の形。

### 実測（2026-07-31）— セッション初の非ゼロ

```
                判別率        騙せた試行   対応ありペア（対 writer）
writer          94% (58/62)      4/62     —
writer_human    82% (51/62)     11/62     6 / 1 / 24   ← 帰無対照の床（1）を超えた
writer_agent    95% (59/62)      3/62     1 / 2 / 28   ← 床のまま
```

`writer_agent` が床にとどまったのが効いている。プロンプト・ゲート・サンプラー・ピン止め機構は
両アームで同一なので、**機構ではなく素材が動かしている**と言える。絶対採点も独立に同じ向きを
指した（70.5 / 人間判定 8% 対 75.3 / 0%）。

**ただし増分の6割が1記事（機械学習 6/8）に集中しており、それを除くと 5/54 対 4/54 で
区別がつかない。** ペア水準 McNemar 完全検定は両側 p = 0.125。交絡も残る（人間コミットと
エージェントコミットは主題も違い、台帳の非コミット項目は両アームともエージェント産）。

**結論は「素材側にはまだレバーがありそうだ」までで、確定ではない。** 次は同一ピン台帳での反復。
表層（提案A）が帰無対照と区別できなかったのと対照的に、ここには測る価値のある差がある。

## 4. 提案C — 素材供給の工学

### C-1 台帳のピン止め（再現性の穴）

README が自分で見つけている：

```
run1 (12/24)  台帳A (82件)
run2 ( 9/24)  台帳A        ← この2つだけが比較可能
run3 ( 0/24)  台帳B (84件) ← 比較不能
```

`hidden_check.py` は台帳の sha1 を**記録する**ようになったが、**固定はできない**。
`git log` の直近40コミットから作るので、セッション中にコミットが進むと入れ替わる。

必要なのは `--ledger-pin <path>`：一度作った台帳を JSON にスナップショットし、
以後の実行はそれを読む。変異アブレーション（提案A）は台帳が動いたら成立しないので、
**これは提案Aの前提条件**。

### C-2 未解決在庫の拡張

`writer` の強さは「本当に開いているバグ」から来ているのに、実在する未解決は4件しかなく
8トピックで使い回している。捏造では増やせない。だが rig には未採取の未解決素材がある：

- `.rig/runs.jsonl` の REJECT 判定とその理由（実際に落ちたゲート）
- 2回詰まった step に出るギャップ処方箋
- `run-state.json` に残った ESCALATE 状態
- `--isolate` で保全された（＝ ff 合流できなかった）worktree と branch

これらは**実在し、開いており、生成器が作ったものではない**。
`probe_open_items()` として台帳に足せる。ただし §3 の出自漏れが再発する
（エージェントの作業記録である）ので、提案B と同時に評価する必要がある。

## 5. 提案D — 大域計画の遮断（relay の修正版）

`freewrite` が示したのは「均質性はハーネスが押し付けているのではない」だった。
枠を外すとモデルは自前で「発端→実行→照合→結論」を建てる。
つまり均質性は**大域的に計画してから埋める**という生成様式から来ている。

`relay`（記事全体を各パスに見せない）はこれを狙って**悪化**した。
失敗の中身は「各パスが自分用の導入を書き直し、小記事6本のホチキス留めになる」。
節ごとに切ったので、各パスが**節を1本の記事として再計画した**。

修正案：切る単位を「節」ではなく「時点」にする。各パスに渡すのは
**直前パスの最後の2文だけ**＋自分の素材シャードで、タイトル・導入・まとめの生成を禁止する。
接合は機械的に行い、平滑化のパスを置かない。

優先度は提案A〜C より下。理由は、これは生成側の介入なので則2の対象であり、
かつ relay の前例がある。**提案Aの測定器が整ってから**回すべき。

## 6. rig 本体へ返す3つの機構

### 6-1 `/rig:drill --repeat N` — 判定役の分散を測る

drill は現在**検出率**（既知の種を見つけるか）を測るが、
**同一入力に対する判定のブレ**を測らない。ベンチはそれが主犯だったと示した。

同一の成果物を N 回判定させ、sd と二峰性を出す。sd が大きい persona の
単票には意味がないので、**分散に応じてクォーラム票数を決める**のが筋になる。
`--verifier-providers a,b,c` と `--quorum` は既にあるので、
足りないのは「何票必要かを較正から決める」層だけ。

### 6-2 `/rig:drill --ablate` — 講評の因果性を測る

則3の機構化。レビュアーが指摘した欠陥**だけ**を機械的に除去して再判定し、
判定が翻るかを見る。翻らなければ、その指摘は判定の原因ではない＝装飾である。

linkify 実験そのものを rig のレビュアー評価に持ち込む形。
「ゴム印検出」（5票以上 REJECT ゼロ）の次の段として、
**理由が判定を説明していないレビュアー**を検出できる。

### 6-3 `scripts/prose_rhythm.py` の位置づけ確定

このスクリプトは自分で「ADVISORY by design」「閾値は較正されていない」と書いている。
ベンチはその判断を**実測で裏づけた**：形態素 lint をゲート化した `riglint` は
findings 5.5 → 1.0 と改善しながら判定は悪化した。

やるべきことは2つで、順序が逆になりやすい：

- **やる**：`fetch_human_corpus.py` の人間コーパスで閾値を較正する（本人が「proper method」と書いている手続き）
- **やらない**：較正したからといってゲート化する。則2 が待っている

## 7. 何を測っているのかを分ける

README の「未検証の方向」が正しく警戒している通り、素材を人間のものにすると
課題が「AI が人間らしく書く」から「人間の書いたものを再構成する」へずれる。
先にファセットを分けておく：

| ファセット | 素材 | 問い |
|---|---|---|
| F1 生成の自然さ | 生成器が持つ知識のみ（bare） | 素材なしでどこまで行くか |
| F2 接地の効果 | エージェントの作業記録（現 writer） | 実在素材は判別率を動かすか（→ 動く。75%） |
| F3 出自の効果 | 人間が書いた実素材（提案B） | 出自漏れは判別率を動かすか |
| F4 後処理の効果 | F2/F3 の出力＋機械的変異（提案A） | 生成様式に触れずに均質さを崩せるか |

現在の主指標（2択判別・両順序・同字数上限）は4ファセット共通で使える。
**指標を変えずにファセットを足す**のが、これまでのセッションで最も高くついた
教訓（測定器を動かしながら設計を比べていた）への対処になる。

---

## 8. やらないこと

- **絶対採点への回帰。** 二峰性がある以上、単発の点数でサンプル個別の主張はできない
- **講評から拾った特徴量への直接介入。** 必ず単一次元の対照実験を先に通す（則3）
- **決定的検出器のゲート化。** 副次指標としてのみ使う（則2）
- **「人間らしさを足す」型の指示。** hedge・内省・一人称・口語はすでに人間より過剰
- **台帳が違う実行同士の比較。** sha1 が一致しない writer 系の比較は無効
