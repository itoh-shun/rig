# 提案E（シード化した五感・喜怒哀楽）の実測結果

`docs/jp-affect-seed-design.ja.md` §7 の穴埋め。2026-08-07、seed `20260807`、
生成 claude-sonnet-5 / 判定 claude-opus-5。記録は
`results/2026-08-07-bare.json`・`2026-08-07-newstrategy.json`・
`2026-08-07-newstrategy-discrimination.json`。

**結論を先に書く。五感・喜怒哀楽の供給は効かなかった。帰無対照と完全に一致した。**
設計メモに書いた撤退条件に該当するので、閾値・語彙プール・歩幅をいじって再挑戦はしない。

## 1. 判別（主指標）

対戦相手は pre-2023 Qiita 44本（`--opponents 4`）、30ペア×両順序＝60試行/条件。

```
arm                 判別率      正解/試行    騙せた
```

対応ありペア（対 `writer_agent`、騙せる方向 / 逆 / 不動）:

```
writer_sense        0 / 3 / 27
```

### 五感・喜怒哀楽 = ゼロ

`writer_sense` と `writer_sense_null` が **0/3/27 で完全に一致した**。
帰無対照はバイト同一のテキストをもう一度判定させただけのものなので、

> **五感・喜怒哀楽の供給は、同じ文章を判定し直すことと区別がつかない。**

過去の変異アブレーションは床（1ペア移動）を超えられなかったが、今回は**床と小数点以下まで同じ**である。
これで否定された設計は23件目になる。

設計メモの予測との照合:

| 予測 | 結果 |
|---|---|
| `writer_sense` は床である確率のほうが高い | **的中**（床と完全一致） |
| `writer_sense_label` < `writer_sense` | **未実施**（本体がゼロなので走らせる意味が消えた） |
| `writer_sense_flat` は床 | **未実施**（同上） |

希少性の機構（`--audit` で emit_rate 0.365、37% の記事は状態を1つも受け取らない）は
設計どおり動いた。**動いたうえで効かなかった**ので、writer_bio 化を避けたことは
正しかったが、避けても結果は変わらなかった。

### spine 固定バグの修正は、判別を良くしなかった

`writer_nostate`（修正前の挙動＝8トピックが同一 incident）が 5/2/23 で、
修正版 `writer_agent` より**わずかに騙せている**。事前予測は逆だった。

ただし帰無対照の床が 0〜3 ペアなので、5/2 は床のすぐ上でしかない。
**「修正が悪化させた」と読むには弱すぎる。** 言えるのは「均質さの原因は spine 固定
だけではなかった」までで、実際、未解決エントリは台帳93件中**4件しかない**（提案 C-2 の
未着手項目）。同じ2本の落ちているテストが、修正後もほぼ全記事の締めに出ている。

## 2. 床が動いた — 測定器の問題

同じ手続き（`mde_calibration.py prepare --levels 0,1.0`）で作った
「候補そのものが人間の記事」条件が、プールによって別の値を出した。

```
2026-07-31 の陽性対照   69.4%  (43/62)   ← chance より 19 ポイント上
2026-08-07 の本実行     30.2%  (19/60)   ← chance より 20 ポイント下
```

**ほぼ 50% を挟んだ鏡像**である。中身を確認したところ、床アームは本物の人間記事
（Qiita アドベントカレンダー 2912字）で、偽物ではない。原因は素材の非対称で、
ドナーは pre-2022 取得・中央値 3425字、対戦相手は pre-2023 取得・中央値 2949字で
下は 937字まで含む。つまりこの条件が測っているのは人間らしさの上限ではなく、
**人間2集団のどちらが濃いか**である。

> **「人間と相違ない」の基準値は、この装置では定数として存在しない。**
> 人間同士を当てさせても 50% にならず、どちらの人間集団を候補側に置くかで
> 30.2%〜69.4% まで動く。

`docs/jp-indistinguishability-criterion.ja.md` の「目標は 69.4%」は**強すぎた**。
正しくは「69.4% はあるプールでの実測値であり、装置の定数ではない」。
`indistinguishable.py` の定数と出力の注記を実測に合わせて直した。

### それでも結論は動かない

床をどこに置いても判定は変わらない:

```
床 0.302 → DIFFERENT  差 +66.7  CI[+63.5, +69.8]
床 0.500 → DIFFERENT  差 +46.9  CI[+43.8, +50.0]
床 0.694 → DIFFERENT  差 +27.5  CI[+24.3, +30.6]
```

3アームとも、どの床に対しても点推定がマージン（±10ポイント）の外にある。
**トピックを増やしても同等にはならない。必要なのはデータではなくアームの改善である。**

事前に「`UNDERPOWERED` が返る確率が高い」と書いたが、外れた。
検出力不足で見えないのではなく、**差が大きすぎて明確に見えている**。

## 3. 絶対採点（弱い指標・参考）

```
arm               平均   中央値   人間判定   サンプル別スコア
bare              87.7   87.8      0%
writer_agent      78.0   78.7      0%      72 73 75 79 79 79 83 84
writer_sense      70.1   78.5     12%      11 74 76 78 79 79 79 84
writer_nostate    62.5   72.0     17%      12 50 66 72 72 74 76 79
```

**中央値はほぼ横一線**（78.7 / 78.5 / 72.0）で、平均差は突破サンプル1〜2本が作っている。
このベンチの規則どおり、絶対採点で順位はつけない。判別（§1）が主指標であり、
そこでは `writer_sense` が最下位である。

ただし**2本は安定した突破**だった。これは既知の二峰性ノイズとは別物として記録する:

```
writer_nostate チーム開発  12.0  sd 0.00  3回=12/12/12
writer_sense   機械学習    10.7  sd 1.89  3回=12/12/8
writer_nostate 機械学習    49.7  sd 29.69 3回=8/75/66   ← これはノイズ
```

人間コーパスの較正平均は 11.06 なので、上2本はその帯に入っている。
講評が挙げた理由は再定義メモの予測どおりで、五感にも喜怒哀楽にも触れていない:

> 実際のコミットハッシュ・テスト名・126という予期せぬ終了コードといった**未解決のまま
> 終わる不揃いな作業ログ特有の質感**／脱線を自分で打ち切る言い回し

`writer_sense` の突破本は、**このベンチ自身の判定分散データ**（同一入力で 9・62・68）に
ついて書いた記事だった。効いたのは五感ではなく台帳の measurement エントリである。

## 4. 判定役は相手の定型さで決めている（再確認）

見破られなかった62試行の講評を読むと、候補ではなく**対戦相手**を落としている:

> 記事Aは体裁の整った Advent Calendar 風の定型的な体験談で構成が均質すぎる
> 記事Aは網羅的なリンク集を均質な見出し構成と定型的な太字強調で並べた
> 記事Aは典型的な合格体験記のテンプレートに沿い

再定義メモの「勝ち講評の最頻項目は 39/47 で『相手が定型的に見えた』」がそのまま再現された。
今回は対戦相手プールを `--min-chars 900` まで緩めたので、定型的な短い記事が増えた可能性がある。
**これは今回の高い「騙せた」数（62/420）の解釈に直接効く**ので、性能向上として読まない。

## 5. 何を持ち帰るか

1. **五感・喜怒哀楽は否定。** 帰無対照と完全一致。撤退条件に従い、パラメータ調整での再挑戦はしない。
2. **床は定数ではない。** プールごとに実測する（`--floor-arm`）。`--floor-rate` は根拠を書ける時だけ。
3. **人間との差は依然として 54〜67 ポイント。** どの床でも `DIFFERENT`。
   残っているのは測定器の拡張ではなくアームの改善である。
4. **未解決在庫が4件しかない**のは、spine 固定バグとは別の、まだ生きている制約（提案 C-2）。
   修正後も同じ2本の落ちているテストがほぼ全記事の締めに出ている。
5. **未実行のまま残るもの**: M9（Markdown アブレーション）。今回のプロファイルで
   **予測が反転した** — bare は箇条書き・画像・表・コードがすべてゼロで、人間側（Qiita）の
   ほうが記法が濃い。剥がすと消えるのは人間側の指紋なので、判別は**下がる**はず。

## 6. この実行の限界

- **n=8 記事/アーム、30ペア/条件。** 対応ありペアの移動が数個の差は読めない。
- **対戦相手プールが過去実行と違う**（`--min-chars 900`、44本）。過去の判別率と直接比較しない。
- **`writer_sense` は 120 試行**。床アーム構築時に source arm として二重に入ったため。
  率は両方 96.7% で一致しているので結論は変わらないが、試行数は他アームの2倍である。
- **床アームのドナーと対戦相手の取得条件が違う**（§2）。この非対称が床を押し下げている。
