# 12設計・1700判定して一歩も進まなかった話 — そして最後に、測っていたものが分かった

前回の記事（[AIの品質ゲートは、測らないと平気で嘘をつく](jp-natural-writing-benchmark.ja.md)）は、
16のハーネス設計のうち効いたのが1つだけだった、という記録だった。効いた1つは `writer` —
実在の成果物を閉じた台帳として渡し、台帳にない固有名詞を機械的に差し戻すアーム。
人間記事との直接対決で4回に1回勝つ、というのが到達点だった。

この記事は、その続きを6設計ぶん回して、**1つも動かなかった**記録である。
最後に、なぜ動かなかったのかが分かった。

## まず、前回の数字が消えた

「4回に1回勝つ」は再現しなかった。原因は測定側にあった。判別テストは対戦相手を
トピックあたり**1本しか使っていなかった**（`by_topic.setdefault`）。1条件16試行で、
騙せた4件のうち2件は較正時に唯一誤判定された機械翻訳調の記事が相手だった。

対戦相手を31体に広げると、判別率は 75% ではなく **94% (58/62)** になった。
騙せた相手は 3/31。トピックあたり第1相手だけに絞っても 15/16 なので、
差はプールの大きさではなく**相手の顔ぶれ**にある。

検出力も足りていなかった。騙せた試行が 2/16 の水準で、その倍化を検出力80%で見るには
**1条件あたり約150試行**が要る。同一ペアの再判定は相関するので効かない。
増やすべきは相異なる対戦相手だった。

## 変異アブレーション — 生成器から見えない介入

前回の教訓に「検査可能な要求には均等充足の抜け道がある」がある。
`rig2` は「脱線を入れろ」と要求して等間隔の脱線を得たし、`riglint` は文長分散の閾値に
短文の等間隔挿入で応えた。**均等に演じられた人間らしさは、それ自体が指紋である。**

この則を回避する方法が1つだけある。**生成後に機械が適用する変異は、生成器から見えない。**
満たすべき対象が存在しないので、均等充足しようがない。

前回、sha 言及18箇所を実在URLへ機械置換して判別が 14/16 → 14/16 と1ペアも動かなかった
実験がある。あの形式を一般化した（`mutate.py`）。

そして今回いちばん効いた判断は、**帰無対照を先に置いたこと**だった。
バイト単位で同一のテキストをもう一度判定させ、対応ありペアで何ペア動くかを測る。

```
                   判別率        対応ありペア（騙せる方向 / 逆 / 不動）
writer (基準)      94% (58/62)   —
writer_null        94% (58/62)   1 / 0 / 30   ← バイト同一の再判定
writer_m5 (丁寧体)  92% (57/62)   1 / 0 / 30
writer_m3 (内省削除) 94% (58/62)   0 / 0 / 31
writer_m1m3        94% (58/62)   0 / 0 / 31
writer_m6 (文分割)  94% (58/62)   1 / 1 / 29
```

**同じテキストを再判定するだけで1ペア動く。** どの変異もその床を超えなかった。
155のペア観測に対して、全変異の移動量の合計は騙せる方向2・逆方向1。

M5 が特に強い証拠になった。丁寧体率は残った特徴量ギャップの最大（人間 65.2 対 writer 0.0）で、
機械変換で 67.8 とほぼ正確に閉じられる。それでもゼロだった。
リンク（d=1.73、ゼロ）と合わせて2例目なので、
**特徴量の分離の大きさは介入の価値を予測しない**は法則として扱ってよい。

## 文長リズムのギャップは、分析器のバグだった

M2 として「隣接文を結合して文長分散を上げる」変異を設計した。根拠は記録されていた
「人間 sent_len_stdev 126〜169 対 AI 20〜36」というギャップ。

そのギャップは `analyze_gap.sentences()` の欠陥だった。`。` だけで分割していたので、
人間 markdown の画像埋め込み・箇条書き・表の行がすべて隣接文に連結されていた。
最長の疑似「文」はこれである。

```
'![スクリーンショット 2022-12-25 23.26.26.png](https://qiita-image-store.s3.ap-northeast-1...'  (186字)
'* なぜこのシステムを作ったのか\n* 使用するツール・環境\n* MACアドレスについて...'                    (121字)
```

アームはこの種の行をほとんど出さない（行の 1.8% 対 コーパス 33.4%）。
**片側にしか効かないアーティファクトが、人間/AI ギャップを製造していた。**

非散文行を落とし、終端記号を持つ単位だけを両側同じ基準で数え直すと：

```
              旧 sd     新 mean   新 sd
人間 (n=48)   143.9      44.5      24.3
writer         36.0      53.8      29.3   ← 既に人間より長く、分散も大きい
bare           18.9      50.3      18.9
```

人間はアームより**短い**文を書く。writer の文長分散はすでに人間を超えている。
`low_burstiness` を上げる方向の介入は、hedge や内省と同じく**過剰な側にさらに積んでいた**。

M2 は破棄して、逆向きの M6（長文を節境界で割る）に作り直した。それもゼロだった。

## 素材が本物である必要は、なかった

`writer` 系の全設計が乗っている前提が1つある。**実素材が効いている**。
だが判定役は read-only で、コミットハッシュも `elapsed_s` も一度も検証していない。
効いているのが「実在すること」なのか「転記されたものの形」なのかは、分離されていなかった。

検証可能な値を**同形の非実在値へ一貫置換**した（同じ実在値は常に同じ偽値へ写すので、
内部の相互参照は壊れない）。桁数・16進長・指数形式は保存。記事8本でユニーク12件。

```
d6d42af                          →  6dcfb47
elapsed_s=9.525999757897807e-06  →  elapsed_s=9.696873935431822e-06
```

騙せた試行は基準 10/62 に対し偽造 10/62。**集計値まで完全一致**した。
帰無対照（8/62）のほうが基準から遠い。

> **判定役にとって、素材が実在する必要はない。必要なのは転記されたものの形だけである。**

これは封じ込めゲートの正当化を組み替える。ゲートの価値は「本物であること」ではない。
捏造した索引上限は**検証する人間の読者に**露見するし（これは文体ではなく正確性の性質だ）、
閉じた在庫は尽きるし余る。前者は十分な理由だが、後者とは別の理由である。

実装中に1つバグを潰した。指数表記と長小数の正規表現を別々の `re.sub` で回していたため、
小数パターンが偽造済みの仮数部に再突入して `9.935431822939974e.-06` という壊れた数値を
作っていた。壊れた数値はそれ自体が生成物の痕跡なので、**そのまま測っていたら偽造の効果として
計上されるところだった**。

## 余剰も、出自も、経歴も

ここまでの否定を受けて、定義を組み直した。勝ち講評が挙げるものを並べると、
どれもテキストの性質ではない。実在の識別子は外を指す指示子だし、有効数字16桁は作文ではなく
転記でしか出ないし、未解決の締めは世界の側が終わっていないということだし、
「今回の主題ではない」と切られた余談は、記事が必要とする以上の素材を持っていた証拠である。

> 人間らしさとは、テキストが「自分より大きい有限の世界からの標本」であることの痕跡ではないか。
> 人間は余剰から書いて捨て、モデルは不足から書いて埋める。

この定義は既存の否定結果を1つずつ説明できた。M4（機械的な末尾切断）がゼロだったことも
事前に予測する — 切断は世界が尽きた痕跡ではなく、テキストを切っただけだからだ。

説明できたので、予測を測った。同一のピン台帳で spine を固定し、**未使用の素材の数だけ**を
0 / 2 / 12 に振る。予測は「余剰が増えるほど判別が下がる」。

```
writer_agent (基準)  95%   3/62    —
writer_k0 (余剰 0)   95%   3/62    0 / 0 / 31   ← 1ペアも動かない
writer_k12 (余剰12)  94%   4/62    1 / 0 / 30
```

**外れた。** 余剰ゼロは基準と31ペア全部が一致した。

これは連鎖した。この間に台帳を著者で二分する実験（`writer_human` / `writer_agent`）を
回していて、人間が書いたコミットの台帳が 6/1 で床を超えていた。セッション唯一の非ゼロだった。
だが実在性が効かず（偽造テスト）、余剰も効かない（このテスト）となると、
**あれを説明する機構がひとつも残らない。** ペア水準の McNemar が元から両側 p = 0.125 で
有意でなかったことと合わせて、ノイズだったと読むのが最も素直になった。

ペルソナも試した。「性別・性格・年齢・知識・経歴・実体験・生活習慣で組み立てる」という
方針で、形容詞ではなく**有限の在庫**として渡した。経歴は就いた職のリスト、知識は知っている
ことのリスト。「几帳面な性格」は演じられるが、リストは**ある文を許可し別の文を書けなくする**。

結果は床（2/1）だった。ただし内訳に情報があった。

```
生活習慣 8/8 記事   実体験 5/8   一人称 6/8   知らないこと 0/8
```

「知らないこと」（Rust・Kubernetes・型システム）は**一度も出なかった**。「詳しくない」すら。
無知は関連しないと表面化しない。バグを追っている記事に Kubernetes を知らないことは書けない。
独立したリストではなく、インシデントと交差する形でしか出口がなかった。

そして生活習慣が 8/8 で出て「土曜の午前」が複数記事に現れたのは、均等充足の再来である。

> **台帳が均等充足を逃れるのは、エントリの大半が「使えない」ときだけである。**

## 最後に、測っていたものが分かった

較正は「本物の人間記事を人間と判定できる」ことを保証していた（n=16、平均 11.06、誤判定 1）。
保証していないものがあった。**判定役が人間性の根拠として挙げる特徴が、人間の分布と一致すること。**
そこは誰も確かめていなかった。

人間記事40本を同じ判定役に当て（38/40 が人間判定、平均 8.9）、講評の手がかりを数えた。
生成側は判別の勝ち講評95件を同じ正規表現で数え直した。

```
cue                 人間記事    生成記事
                     (n=38)    (n=95)
実在の識別子              2%       81%
未解決の締め             26%       88%
定型的でない             15%       80%
生の数値               44%       57%
未整理さ               28%       45%
余談・切り捨て            18%       21%
一人称・主観             52%       30%
誤字・崩れ              44%       10%
```

**2つの経路がほぼ交わらない。** アームは実在の識別子・未解決の締め・相手が定型的、で勝つ。
人間記事が人間と判定される理由の上位2つは一人称・主観と誤字・崩れで、
アームが不足しているのはそこだけである。

そしてアームは自分の経路で 81〜88% に達している。**押す余地が残っていない。**
そこを強化する設計 — 12設計がやってきたこと — は、定義上もう動かない。

もう1つ、副産物の数字がある。ジャンル統制を試した際にコーパスを型で比べたとき出た。

```
未解決で終わる人間記事   0 / 139 本
```

勝ち講評で2番目に多く挙げられていた「未解決のまま終わる」は、
**人間の Qiita 記事が事実上一度もやらないこと**だった。
判定役の「人間」は参照集団の記述ではなく、**規範**である。

（そのジャンル統制自体は失敗した。Qiita の全文検索語は本文のどこかに現れればヒットするので、
引き直した91本は文書の型が元と変わらなかった — 「はじめに」見出しはむしろ 31% → 44% に増えた。
ジャンル交絡は否定されたのではなく、依然として未検証のまま残っている。）

## 副産物

前回同様、ベンチを回すたびに本体の不備が出た。今回は3件が測定を歪めていた。

`writer_ledger._run` が道具の不在を黙殺していた。pytest 未導入の環境では
`python3 -m pytest` が終了コード1・標準出力空・stderr に "No module named pytest" を返し、
`probe_test_failures` はこれを「落ちているテストは無い」と読む。実測で台帳が
**89件中 未解決1件**になっていた。未解決素材は writer アームが効く理由そのものなので、
これを直さずに出自実験を回していたら「素材を変えても何も起きない」という誤った結論が出ていた。

実行記録の台帳フィンガープリントが、アームが実際に使った台帳ではなく既定の台帳を書いていた。
使っていない素材の指紋が記録に残るのは、比較可能性を保証しているように見えて
**無効な比較を許可する**ので、フィンガープリントが無いより悪い。

そして live 実行を2回失った。1回目はトレースバックも進捗もなく7分で消え、
2回目は `writer_k0` の 6/8 まで進んだところで消えていた。同じコードで別バッチは完走している。
数十分ぶんの生成がメモリにしか無い設計だったので、完了済みのサンプルごと消えた。
進捗出力と `--checkpoint`（完了サンプルを即座に JSONL へ追記し再開時に読み直す）を足した。
**1行しか出力しない1時間半のジョブは、ハングと死亡と正常進行が区別できない。**

## 開いたままのもの

このセッションで約1700回判定して、帰無対照の床を超えたものは1つもなかった。
表層6条件・素材の実在性・余剰・出自・経歴ペルソナ・ジャンル、すべてである。

生成側を押し続ける根拠は、もう無いと思っている。判定役が報いる特徴は飽和しており、
人間が人間と判定される経路にはアームは乗っていない。

残っている手がかりは1つだけある。**誤字・崩れ**は人間側 44% 対 生成側 10% で、
一人称・主観と並ぶ最大の不足だ。誤字注入（M8）は床の内側だったが、
試したのは仮名の置換3箇所（`という`→`とゆう` 等）だけで、判定役の言う「誤字・崩れ」は
変換ミス・表記ゆれ・文の崩れを含む。**試したのは手がかりの一部であって、手がかりそのものではない。**

ただし前回と同じ警告が自分に返ってくる。講評から拾った特徴に直接介入して、
2回とも因果ゼロだった（リンク、丁寧体）。上の表は**規範の地図**であって、
不足している2つを足せば動くことは一切意味しない。

`tests/test_bench_providers.py` の `assert 126 == 124` は、まだ落ちている。
