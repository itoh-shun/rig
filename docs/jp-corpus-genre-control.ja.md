# コーパスをプラットフォームの外へ出す

技術記事でない人間の散文（個人ブログ・エッセイ・話し言葉）を対象に加えるための設計と、
その前提になる測定器のメモ。実装は `corpus_profile.py` と `fetch_prose_corpus.py`。

> **判定はまだ1本も回していない。** 載っているのは文書型のプロファイル（モデル不要・決定論）と、
> それが可能にする実験の予測だけである。判別率・スコアの数値はここには無い。

---

## 1. E3 はなぜ失敗したか — プラットフォームの中ではジャンルを変えられない

`docs/jp-humanness-redefinition.ja.md` §4 が問題を立てている。

> この指標は、著者性（人間かAIか）とジャンル（作業ログか紹介記事か）を分離できていない。
> いま測っているものの一部は「これは Qiita 記事らしいか」であって「これは人間が書いたか」ではない。

勝ち講評の最頻項目が **39/47 で「相手が定型的に見えた」**（候補の性質ではなく対戦相手の性質）
だったことが根拠になっている。

E3 はこれを Qiita の全文検索語（「ハマった」「原因」「備忘録」）で直そうとして、失敗した。
91本を取り直して判別率は**上がり**、しかも操作の検証を後回しにしていた。

```
                 n    はじめに見出し   画像   表    未解決で終わる
既定コーパス      48       31%        56%   13%      0%
ジャンル統制      91       44%        52%   13%      0%
```

**文書の型が1つも動いていない。** Qiita の全文検索は本文のどこかに語があればヒットするので、
チュートリアルの調査パートが引っかかる。そして何を引いても結果は Qiita 記事のままである。

> **テンプレートから出るには、プラットフォームから出るしかない。**

これが「技術寄りでないものを取りに行く」ことの、このベンチにおける正確な意味になる。

---

## 2. 先に測定器を作る

E3 の本当の失敗は検索語ではなく、**操作が効いたかを事後にしか確かめなかった**ことにある。
その確認は使い捨てのコードで、スクリプトとして残っていなかった。

`corpus_profile.py` はそれを常設にしたもの。任意のコーパスディレクトリを、
モデルを呼ばず・ネットワークも使わず、1つの物差しで測る。指標を3群に分けてあるのが要点：

- **form** — 見出し・箇条書き・画像・表・コード。**記事のテンプレート**。Qiita が強制し、
  個人ブログや講演が持たないもの。
- **register** — 丁寧体率・一人称・疑問符・体言止め。**声**。
- **shape** — 文長・段落・未解決で終わるか。

ジャンル統制が **form を動かさなければ、それはジャンルを変えていない**。E3 はそこで失敗した。

### 測定器自身のバグを1つ踏んだ（R2 の再演）

最初の HTML 抽出は本文をプレーンテキストに潰していた。その結果がこれ：

```
              Qiita    ブログ
headings/1k    3.41  →   0.0
画像 %         66.7  →   0.0
表 %           20.0  →   0.0     ← 全 form 指標が正確にゼロ
```

**ジャンル統制が完璧に効いたように見える。** 実際には Qiita は API から markdown で届き、
ブログは HTML を剥がした素のテキストで届いていただけで、差は抽出器が作っていた。

R2 が記録した失敗と同型である（`analyze_gap.sentences()` の分割バグが人間側にだけ効いて、
存在しない文長ギャップを製造した）。**片側にだけ効くアーティファクトは、集団間の差を捏造する。**
`html_to_text` は見出し・箇条書き・画像・表・コードを markdown 記法へ**変換**するように直し、
`tests/test_corpus_profile.py` がそれを固定している。

## 3. パイロット実測（2026-08-07・判定なし）

`fetch_prose_corpus.py --source hatena` で、はてなブックマークの日付付き RSS 検索から
2018〜2022 の個人ブログ（日記・読書感想・料理）を取得。Qiita 側は同日の再取得。

```
                    Qiita(n=15)   個人ブログ(n=12)
── form
  headings/1k             3.41        1.61
  はじめに見出し %            60.0        25.0
  bullets/1k              3.35        4.22
  画像 %                   66.7        83.3
  表 %                     20.0         0.0
  コード %                  26.7         0.0
── register
  丁寧体 %                 35.77       24.78
  一人称/1k                  0.50        1.81
  疑問符/1k                  0.71        1.16
  体言止め %                 8.41       12.58
── shape
  文長 mean               43.09       28.22
  文長 sd                 36.96       22.06
  段落あたり文数              2.96        1.55
  未解決で終わる %             6.7         0.0
  平均字数                 2835.0      1995.5
```

**E3 と違って、今度は form が動いた。** 「はじめに」見出しは 60% → 25%、表とコードは消える。

そして**箇条書きと画像は逆に増える**（3.35 → 4.22、66.7% → 83.3%）。
抽出器のバグ版はこの2つを「ゼロになった」と報告していたので、
**修正しなければ結論の向きごと間違えていた。**

register の差のほうが大きい。一人称が **3.6倍**（0.50 → 1.81）、文長が **43 → 28字**。
R2 の実測では人間 Qiita が 44.5字・`writer` アームが 53.8字で、アームは既に人間より長い。
個人ブログを基準に置くと、**その差はさらに開く**。

> **注意：n=15 / n=12 のパイロットである。** 1回の取得・1日・少数トピックで、
> 信頼区間は付けていない。読めるのは「form が動いたか」までで、各数値の大小ではない。

## 4. 用途を3つに分ける（混ぜると交絡が増える）

新しいコーパスは万能の改善ではない。**使い道ごとに効果が逆になる。**

| | 使い方 | 何が分かるか | リスク |
|---|---|---|---|
| **P1** | 判別の対戦相手を個人ブログに差し替える | 82〜98% のうちどれだけが「Qiita 記事らしさ」だったか | アームは作業ログのまま。ジャンル交絡は**残る**（向きが変わるだけ） |
| **P2** | 判定役に人間テキストだけを採点させる（`judge_norm.py`） | 判定役の「人間らしさ」が文書型の規範なのか | ほぼ無い。生成不要・最も安い |
| **P3** | 話し言葉を対戦相手に入れる | — | **やってはいけない**（§5） |

**P2 が本命である。** 較正が保証したのは「人間の Qiita 記事を人間と判定できる」
（平均 11.06・誤判定 1/16）ことだけで、それが**Qiita 以外の人間文にも成り立つかは未検証**だった。

### P2 の予測

判定役の「人間らしさ」が文書型の規範なら、**人間が書いたものでも、記事の形から離れるほど
AI 寄りに採点される**はずである。

```
予測:  Qiita 記事（人間）  <  個人ブログ（人間）  <  講演の書き起こし（人間）
       平均 11 前後            より高い              さらに高い
```

- **この順に上がったら**：現行指標の測っているものは相当部分が「記事らしさ」であり、
  「目標水準は 11 前後」という較正の読みは**ジャンル限定**だった。22設計が動かなかったことの
  説明にもなる（アームは規範側の特徴を飽和させていて、規範は人間の分布と一致していない）。
- **上がらなかったら**：判定役はジャンルに依らず人間を人間と判定できる。
  §4 のジャンル交絡は否定され、82〜98% は著者性を測っていたことになる。

**どちらに転んでも大きい。** そして生成が要らない。

### 補強材料が1つ既に出ている

`未解決で終わる` は個人ブログでも **0.0%** だった（Qiita は今回 6.7%）。
判定役が人間性の根拠として2番目に多く挙げた特徴（34/47）は、
**2つ目の人間集団でもほぼ現れない。** 規範仮説はこれで少し強くなる。

## 5. 動画コンテンツの扱い

`--source local` が `.srt` / `.vtt` / `.txt` を取り込み、タイムコードとキュー番号を落とし、
連続重複行（ロール字幕は前行を繰り返す）を畳んで散文に戻す。取得ではなく**取り込み**なのと、
`mode=spoken` を必ず付けるのには、別々の理由が2つある。

**1. 自動生成字幕は人間が書いた文ではない。** ASR の出力＝機械が人の発話を書き起こしたもので、
これを「人間のテキスト」として採点すると、パイプラインに2台目の機械が入り、
その癖を話者に帰属させることになる。人が作った字幕・書き起こしだけが対象になるが、
**その区別は供給する人にしか分からない。** 取得スクリプトには判別できないので、判別するふりをしない。

**2. 話し言葉は書き言葉ではない。** 書き起こしには見出しも箇条書きも画像も無い。
これを判別の対戦相手プールに入れると、判定役は**レイアウトで**自明に分離する。
著者性ではなく体裁で当たるので、**ジャンル交絡は改善どころか悪化する**。前に進んだように見えて。

だから話し言葉は P2（規範プローブ）専用にする。`fetch_prose_corpus.py` は
`mode=spoken` で書き出すときに警告を出し、`index.json` に記録する。

### 書き起こしのプロファイルはこう出る（合成字幕での動作確認）

```
                    Qiita    個人ブログ   書き起こし
headings/1k          3.41      1.61        0.0
画像 %               66.7      83.3        0.0
丁寧体 %             35.77     24.78       84.0
文長 mean            43.09     28.22       15.4
段落あたり文数         2.96      1.55      119.0   ← 数値として読まないこと
```

form は総崩れ、register は逆に高い。**§4 の予測（form から離れるほど…）を測るための軸が
実際に取れている**ことの確認になる。

ただし **`段落あたり文数` は話し言葉では未定義**である。字幕には空行段落が無いので、
文書全体が1段落として数えられて 119 になる。これは発見ではなく指標の適用外で、
話し言葉のプロファイルを読むときは form と register だけを見る。

## 6. 実行

```bash
# 0. 取得（本文はコミットしない。第三者の著作物）
python fetch_human_corpus.py --out /tmp/human_corpus                      # Qiita（既存）
python fetch_prose_corpus.py --source hatena --out /tmp/blog_corpus
python fetch_prose_corpus.py --source local --in ~/subs --out /tmp/talk_corpus --mode spoken

# 1. 操作が効いたかを先に確認する（無料・モデル不要）。E3 はここを後回しにして失敗した
python corpus_profile.py /tmp/human_corpus /tmp/blog_corpus /tmp/talk_corpus

# 2. P2 規範プローブ。生成不要。judge_norm は index.json の file だけ見るので3つとも通る
python judge_norm.py --corpus /tmp/human_corpus --json-out results/YYYY-MM-DD-norm-qiita.json
python judge_norm.py --corpus /tmp/blog_corpus  --json-out results/YYYY-MM-DD-norm-blog.json
python judge_norm.py --corpus /tmp/talk_corpus  --json-out results/YYYY-MM-DD-norm-talk.json

# 3. P1 は P2 の後。form が動いていることを 1 で確認してからでないと意味がない
python discriminate.py --corpus /tmp/blog_corpus --opponents 4 --run results/<既存>.json
```

**手順1で form が動いていなければ、2 へ進まない。** それが E3 から持ち帰る唯一の手続き上の教訓。

## 7. 限界

- **n が小さい。** パイロットは 15 対 12。P2 を回すなら各30本以上は欲しい。
- **はてなブックマークは個人ブログ以外も索引している。** ホスト名で
  `hatenablog.com` 系に絞っているので、**「はてな記法の個人ブログ」という別のプラットフォーム
  バイアス**が入る。Qiita バイアスを、はてなバイアスに置き換えただけの可能性は残る。
  複数プラットフォームに広げるまで、これは解けない。
- **ブックマーク数 3 以上のフィルタは人気バイアスを入れる。** 読まれた文章は編集されている。
- **pre-2023 の切りはブログにも適用しているが、Qiita ほど安全ではない。**
  個人ブログの投稿日は自己申告で、後から編集されうる。
- **話し言葉コーパスは供給者依存。** 誰がどの講演を選ぶかで register が動く。
- **P1 をやってもジャンル交絡は消えない。** アームが作業ログを書く限り、
  対戦相手を日記にしても「作業ログ 対 日記」になるだけである。交絡の**向きが変わる**ので
  2方向から挟めるが、片方だけでは解決にならない。
