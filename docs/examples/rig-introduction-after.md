# RigでAI開発を「作業」から「検証できるフロー」に変える

AIにコードを書かせるだけなら、チャットツールでも始められます。Rigは、その先にある「設計・実装・テスト・レビュー」を、再利用可能な開発フローとして組み立てるためのワークベンチです。

## Rigでできること

Rigの中心にあるのは、作業手順を定義した **recipe** と、各工程を表す **step** です。たとえば、次のような流れを1つの作業単位として扱えます。

1. 依頼内容と受け入れ条件を整理する
2. 実装を行う
3. テストを実行する
4. 独立したレビューで差分を確認する
5. 条件を満たしたか判定する

レシピはプロジェクトごとに選択でき、必要ならレビューやTDDなどの工程を追加できます。単発の質問は通常の会話で済ませ、複数工程の変更だけをrecipeに載せる、という使い分けも可能です。

## 最小の実行例

まず、作業内容を自然文で渡します。

```sh
rig-wb run "ログイン処理のバグを直す"
```

Rigは依頼の種類に応じてrecipeを解決し、実行するstepと受け入れ条件を表示します。実装だけでなく、テストやレビューまで含めた結果を確認してから完了にできます。

## AIに任せきりにしないための仕組み

Rigのポイントは、AIの出力をそのまま正解にしないことです。受け入れ条件、テスト、独立レビュー、変更範囲の確認をゲートとして扱います。レビューで条件を満たさなければ、修正するか、未完了として止めます。

そのため、Rigは「AIが必ず正しいコードを書く」ツールではありません。どの条件を満たせば完了とするかを、作業の最初に明示するための道具です。

## どんなときに使うか

- 小さな質問やアイデア整理：通常の会話
- 1ファイル程度の修正：短いrecipeまたはad-hoc実行
- 複数ファイルの変更：実装・テスト・レビューを含むrecipe
- リリース前の確認：受け入れ条件と独立レビューを含むフロー

最初から大きなフローを選ぶ必要はありません。作業の規模と失敗時の影響に合わせて、必要な工程だけを組み合わせるのがRigの使い方です。

## まとめ

Rigは、AIに作業を丸投げするためのショートカットではありません。AIを使った開発を、手順・検証・停止条件つきの再利用可能なフローにするためのワークベンチです。
