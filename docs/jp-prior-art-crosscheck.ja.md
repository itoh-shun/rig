# 先行文献との突き合わせ

外部の「AI っぽさ」論・検出手法の主張を、このリポジトリが既に実測している記録に照らして
仕分けたもの。**新しく測る前に、既に死んでいる仮説を捨てるため**の文書。

なぜ突き合わせが安いか。このリポジトリは 22 設計・約 500 判定ぶんの「効かなかった記録」を
持っている。外部の主張の多くは、その記録に当てるだけで**生成を1本も回さずに**判定できる。

> 引用はすべて要約・言い換えであり、原文の本文・例文は転載していない。

## 突き合わせ表

凡例 — **反証**: 実測で否定済み（採用しない） / **裏づけ**: 実測が既存カタログを支持 /
**射程外**: 主張は妥当でもこの判定役では原理的に測れない / **未検証**: 実験候補（=価値がある）

### 反証されたもの（外部・内部の双方で）

| 主張 | 出典 | 実測 | 状態 |
|---|---|---|---|
| 同一語尾（です・ます）の連続は AI の徴候 | 通説 | S1 が棄却（丁寧体では議事録・答弁・講演録で人間も自然に連続）。**本リポジトリでも独立に再現** — 旧閾値3で人間文書の56%が発火 | **反証（二重）** |
| 「これにより」は人間はほぼ使わない | 実務者間の通説 | S1 実測で**人間側のほうが多い**。個人の書き癖だった | **反証** |
| 同型構文の修辞的反復は AI | 通説 | S1: 随筆の修辞技法・答弁の定型を誤検知し、**むしろ人間側で高発火** | **反証** |
| 序数による列挙は AI | 通説 | S1: 実務文書の正常な作法。群間の弁別力なし | **反証** |
| 体言止めの多用は AI | 通説 | S5: **AI はほぼ使わず人間が混ぜる**（向きが逆） | **反証**（収録済み） |
| 文頭反復は AI | 通説 | S5: 人間側の93%の文書に文頭反復あり | **反証**（収録済み） |
| 文長のばらつきを増やせば人間らしい | How-to 記事群 | R2: 人間 44.5字 / `writer` 53.8字 — **アームは既に人間より長く分散も大きい**。増やす介入は過剰側に積む | **向きが逆** |
| 口語・カジュアル化（「〜なんです」）で人間らしく | How-to 記事群 | 則2＋マーカー L。`rig2` は等間隔の脱線、`riglint` は等間隔の短文挿入で応え、lint 5.5→1.0 と改善しながら**ブラインド判定は悪化** | **反証** |

**この列の実務的な意味**：ネット上の「AI っぽさ」チェックリストの相当部分は、実測すると
人間の正常な文章への誤検知になる。S1 の言い方を借りれば、印象ベースのルールは高い確率で
人間の正当な文章を誤って指摘する。

### 裏づけられたもの

| 主張 | 出典 | 実測 | 対応する既存マーカー |
|---|---|---|---|
| 三段構成（導入→本論→結論）の型どおりさ | S1 | AI 44% / 人間 6.7% | **O**（教科書配列） |
| メタ言及（「まとめると」「本稿では」） | S1 | AI 42% / 人間 6.7% | **I**（自己言及メタ）／`prose_rhythm` の `progress` |
| 律儀な結論（最終段落を全体要約＋一般論で締める） | S1 | AI 72% / 人間 20%（感度は最大だが偽陽性も高め） | **M**（きれいすぎる解決） |

3項目の論理和で S1 の AI 群 80% をカバーする。
**外部の対比コーパスがこのカタログの深層マーカーを独立に裏づけた初の例**であり、
同時に「表層の語彙ではなく文書の構成を見ろ」という判定優先順位（深層→言語→表層）を支持する。

### 射程外 — 妥当だが、この判定役では測れない

| 主張 | 出典 | なぜ射程外か |
|---|---|---|
| 本質的な差は**文責**の有無（AI は誤りを平然と書き、責任の概念を持たず、実在しない経験を創作できる） | S4 | **E2 が実測済み**：勝った記事の実在値（コミットハッシュ・16桁浮動小数）を同じ形の非実在値へ機械置換しても、判別は集計値まで一致した。判定役は read-only で実在を検証していない。文責は原理的に本文の外にある |
| 根本原因は「主張の提案と妥当性判断まで委任したこと」 | S1 §5.2 | S1 自身が「これを**表層特徴から推定する方法は未確立**」と明記。本リポジトリの E2 はその困難を実測で裏づけた形になる |

S4 の主張は**規範として正しく、検出機構としては使えない**。文責は書き手が引き受けるもので、
テキストから読み取れる性質ではない。S1 が真偽判定を諦めて「サジェスト」に目的を限定したのも、
S2 の理論的限界（十分高性能な LLM に対しては最良の検出器でもランダム分類器をわずかに上回る
程度）を出発点にしているからで、**方向としては同じ結論に3者が別ルートで到達している**。

### 未検証 — ここに価値がある

| # | 主張 | 出典 | なぜ効くか / どう測るか |
|---|---|---|---|
| **X1** | **Markdown 残骸を除くと従来手法の弁別力はほぼ消える** | S1 §4.2 | S1 では当該カテゴリを外すと AI 群中央値が **71.8 → 7.2** に落ち、人間群との分離がほぼ消失した。「従来手法の実力値は実質的に記号探しだった」。**本ベンチでは未分離** — 判別役は LLM でありルール検出器ではないので自動的には当てはまらないが、`corpus_profile` の form 群がまさにこの軸を測っている。**生成不要**で、`mutate.py` の変異アブレーション機構にそのまま乗る（両側から markdown を除去して再判別） |
| **X2** | **検証済み LLM ルーブリックから項目を削ると、残った項目の判定が反転する** | S1 §5.1 | 6項目→3項目に整理しただけで、メタ言及の人間側偽陽性が **6.7% → 50%** に急増した。LLM は項目リスト全体を文脈として基準を相対的に構成している。**rig 本体に直撃する** — personas / facets / acceptance は項目リストであり、recipe ごとに組み替えている |
| **X3** | 構造判定を小型ローカル LLM に「個別の事実認定を true/false で」やらせる | S1 §3.2 | 総合判断をさせず「三段構成が有るか」だけ答えさせ、点数化は人間可読なルールファイル側で持つ。9B級で応答形式エラー0件・1判定約5秒。rig の verifier 設計（判断は persona、事実は knowledge）と同型 |
| **X4** | 超過語彙（LLM 登場前の頻度から予測される値との差分） | S3 | 英語圏の特徴語（delve 等）は日本語に移植できず、日本語での同種の定量検証は S1 の調査範囲では見当たらない。本リポジトリは pre-2023 人間コーパス取得機構を持っているので、原理的には測れる |

**X1 を最優先にする。** 生成が要らず、既存の変異アブレーション機構に乗り、
そして**当たったら 92〜98% という数字の解釈が変わる**。

**X2 は rig 本体の話**なので、日本語ベンチの外に出す価値がある。

## 今回この突き合わせから実際に直したもの

`scripts/prose_rhythm.py` の run 系閾値を、**人間コーパスで較正した**（リポジトリ自身が
「やる」と書きながら未着手だった項目）。人間文書 27本（Qiita 15 ＋ 個人ブログ 12、いずれも pre-2023）:

```
閾値   ending-run   long-run     ← 人間文書が flag される割合
  3       56%         44%        （旧・閾値が人間の中央値の上に乗っていた）
  4       19%         15%
  5        4%          7%        （新）
  7        0%          0%
```

**旧閾値 3 は人間の中央値そのものだった**ので、構造上ほぼ半数の人間文書が発火していた。
5 に上げて、人間文書の発火率は **74% → 22%** に下がった。

S1 が別コーパス（青空文庫・国会会議録・実務文書）で同じ結論に達しているので、
**重複しない2コーパスによる独立再現**になっている。

較正しても**ゲート化はしない**。それは既に実測で否定されている（`riglint`）。

### この作業中に踏んだ穴（記録）

閾値分布を測る最初の実装で、`normalized_ending` を自前で書き直したところ
`。` と `、` の除去を落としており、語尾が一度もマッチせず「人間の ending-run 中央値は 1」という
**逆の結論**が出た。検出器本体の関数を使い直して 3.0（＝閾値そのもの）に修正。

R2（分析器の文分割バグ）・HTML 抽出の平坦化（`corpus_profile` 開発時）に続いて**3例目**である。
共通しているのは、**測定器を書き直すと、測定器のバグが結論の向きを変える**こと。
既存の検出器がある場合は、再実装せずその関数を呼ぶ。

## 方針として持ち帰るもの

1. **通説は、実測すると高確率で人間の正常な文章への誤検知になる。** S1 が4件、S5 が2件棄却した。
   カタログに足す前に対比コーパスで発火率を比べる（S1 の「仮説→実測→棄却/採用のサイクル」）。
2. **表層の記号は強力に見えて脆い。** 除去された途端に無力になる（X1）。
3. **構成的特徴（三段構成・メタ言及・律儀な結論）は外部実測でも生き残った。** 深層優先は正しい。
4. **「AI らしくなさ」を仕様として定義した瞬間に、その仕様どおり書かせて無効化できる。**
   S1 はこれを理由に人間らしさの定義を意図的に避けている。本リポジトリの則2 と同じ命題であり、
   **別々の設計から独立に到達した2例目**になる。
