# シード化した五感・喜怒哀楽を「素材」として供給する

`writer_sense` 系アームの設計メモ。何を賭けていて、何が外れたら捨てるかを、生成を1本も
回す前に書いておくためのもの。実装は `benchmarks/writing-tasks/jp-natural-writing/affect_state.py`。

> **まだ実測していない。** この文書に判別率は1つも載っていない。載っているのは設計と予測と
> 撤退条件だけである。数値が出たら §7 に追記し、予測が外れていたらそう書く。

---

## 1. 出発点 — 何がうまくいかなかったのか

課題の立て方はこうだった。**機械的な文章は AI と判定される。だから機械的でない文章にしたい。
しかしそれを機械的に直そうとしても、うまくいかない。**

このリポジトリはその「うまくいかない」を22設計・約500判定ぶん測ってある
（`docs/jp-naturalness-engineering.ja.md`、`docs/jp-humanness-redefinition.ja.md`）。
要点は3つで、どれもこの提案の前提になる。

**則1 — ゲートは「要求する」より「絞る」ほうが効く。** 出力に条件を課す設計（要求側）は
全部外れた。効いたのは入力の語彙を閉じる設計（供給側）だけだった。

**則2 — 検査可能な要求には均等充足の抜け道が必ずある。** `rig2` は「脱線を入れろ」と要求して
等間隔の脱線を得た。`riglint` は文長分散の閾値に短文の等間隔挿入で応え、lint findings は
5.5 → 1.0 に改善しながらブラインド判定は**悪化**した。

> 均等に演じられた人間らしさは、それ自体が指紋である。

**則3 — 特徴量の分離の大きさは、介入の価値を予測しない。** リンク密度（人間 5.56 / AI 0.01、
d=1.73、全特徴で最大の分離）を機械置換して 14/16 → 14/16。丁寧体率（人間 65.2 / 生成 0.0）を
機械変換で 67.8 まで閉じて、効果ゼロ。

そして変異アブレーション（`mutate.py`）が**帰無対照つき**でこれを締めた。

```
帰無対照（バイト同一の再判定）    1 ペア移動   ← 床
M5 丁寧体変換                   1 ペア移動
M3 内省の締め削除                0
M1+M3                          0
M6 文長分割                     1 移動 / 1 逆行
```

**「機械的に直す」の側は、もう動かせる次元が残っていない。** これが前回の結論であり、
この提案が生成側・素材側から入る理由でもある。

## 2. 提案 — シードで引いた五感・喜怒哀楽を、記録として渡す

書き手の**状態**を、記事ごとにシードから引いて素材に混ぜる。

- **五感**（視覚・聴覚・触覚・嗅覚・味覚）— そのとき体が何を拾っていたか
- **喜怒哀楽**（喜・怒・哀・楽）— そのとき何を思ったか

引いた状態は台帳の個々のエントリに時系列で紐づき、**その場で書き殴ったメモ**として渡される。

```
＜作業中に手元に書き殴ったメモ＞
（記事の主題ではありません。使えるものがあれば使い、無ければ捨ててください。
  全部に触れる必要はまったくありません）
- ファンが回りっぱなし。静かになったのは 03:40。同じところで3回
```

`python affect_state.py --seed <値> --preview` で1回ぶんの引きが見られる。

### 「シードで乱数を振る」だけでは新しくない

先に潰しておく。**乱数それ自体は、このベンチではもう使われていて、もう効いていない。**

`mutate.py` の M2 は「等間隔に適用したら riglint と同じ指紋になる」という理由で、
適用位置を記事のハッシュを種にした**わざと不均一な分布**から引いている。`hidden_check.merge_runons`
も `_cut_midsentence` も同じ形をしている。それらは全部ゼロだった。

したがってこの提案の賭けは「乱数を入れること」ではない。**乱数が何を選ぶか**にある。
シードが選ぶのは文の切り方ではなく、**書き手がどの状態にあったか**であり、それは
テキストの性質ではなく素材の一部として渡る。則1 の言う供給側に置ける唯一の形がこれになる。

### 要求側に落ちない書き方

「怒りを込めて書いてください」は**要求**である。要求は満たされ、均等に満たされる（則2）。
だからここでは一度も指示をしない。渡すのは「そのときこう書いてあった」という記録だけで、
使うか捨てるかは書き手に委ねる。**満たすべき対象が存在しない。**

## 3. いちばん危ない先行結果 — `writer_bio`

この提案に最も近い既存アームは `writer_bio` で、**床に着地している**（騙せる方向2 / 逆1、
帰無対照の床は1）。経歴・知っていること・知らないこと・実体験・生活習慣を台帳として渡した。

失敗の中身が、そのままこの提案への警告になっている。

```
生活習慣（どの記事にも当てはまる）   8/8 記事で使用。「土曜の午前」が複数記事で反復
知らないこと（ほぼ当てはまらない）   0/8 記事。「詳しくない」すら一度も出なかった
```

記録された教訓はこうだった。

> **台帳が均等充足を逃れるのは、エントリの大半が「使えない」ときだけである。**

**五感と喜怒哀楽は、想像しうる限り最も普遍的に適用可能な素材である。** 体は常にあり、
気分も常にある。素朴に実装すれば「毎記事に必ず身体描写が1つ入る」になり、それは
生活習慣が 8/8 で使われたのと同じ指紋になる。**素朴な版は、writer_bio の失敗を手間をかけて
再現するだけになる。**

## 4. 設計の肝 — 大半を「使えない」状態にする

だから機構の中心は五感でも喜怒哀楽でもなく、**希少性**にある。

台帳のエントリを時系列に辿りながら、覚醒度をシード化したランダムウォークで歩かせ、
**閾値を超えたときだけ**メモを1つ出す。超えなければ何も出ない。

```
THRESHOLD = 0.62          閾値
START     = 0.20〜0.75    初期値（閾値より下に中心を置く）
STEP σ    = 0.28          歩幅
```

結果（`affect_state.py --audit 2000`、1記事あたり5エントリ）:

```
emit_rate          0.365    エントリの 63.5% は何も出さない
moments/article    mean 1.82  sd 1.83  max 5
zero-moment share  0.371    記事の 37% は状態を1つも受け取らない
per sense          視覚 0.34  聴覚 0.25  触覚 0.24  嗅覚 0.09  味覚 0.08
```

読むべきは3つ。

1. **`emit_rate` が 1.0 に近づいたらこのアームは writer_bio に戻っている。** 生成に金をかける
   前に `--audit` で分かる。writer_bio はこの確認を、床に着地して記事を読み返すまで受けなかった。
2. **`zero_moment_share` が 0.37。** 3記事に1本は状態を1つも持たない。**この記事は引き直さない。**
   出るまで引き直す実装にした瞬間、希少性は消えて指紋に戻る。
3. **嗅覚・味覚が稀。** スタックトレースを読むことと匂いには、普通は何の関係もない。
   五感を均等に配ったらそれは記録ではなく演出である。

対照として `--flat` を置いてある。ウォークを止めて全エントリで出す＝`emit_rate` 1.000 /
`sd` 0.00 / `zero_moment_share` 0.000。**writer_bio の均等性を意図的に再現したもの**で、
これが良い設定なのではなく、希少性が効いているのかを切り分けるためだけに在る。

### 語彙は捏造である（意図的に）

メモの文面は架空の固定プールから引く。`writer_ledger.BIOGRAPHY` と同じ扱いで、理由も同じ：
E2（`results/2026-07-31-forgery-typo-discrimination.json`）が、判定役は素材の実在を
一度も検証していないと測っている（偽造ハッシュは集計値まで基準と一致した）。実在の誰かの
体と気分を借りても得るものが無く、借りない理由はある。

**既知の限界**：プールが固定である以上、多数の記事を横断して見れば**プールそのものが指紋**になる。
判定役は1本ずつ見るので今の指標には出ないが、これは指標の性質に守られているだけであって、
設計が解決している問題ではない。

## 5. アームと予測

3本とも `writer_agent` と同じピン台帳・同じプロンプト・同じゲート・同じサンプラーで、
違うのは状態の有無と渡し方だけ。

| アーム | 状態 | 分離したい変数 |
|---|---|---|
| `writer_agent`（基準・既存） | なし | — |
| `writer_sense` | 疎・ドリフトあり・メモ形式 | 状態そのもの |
| `writer_sense_flat` | 全エントリで出す・メモ形式 | **希少性**（対 `writer_sense`） |
| `writer_sense_label` | 疎・「怒 4/5」と名指し | **供給側/要求側**（対 `writer_sense`） |

### 事前に書く予測

- **`writer_sense_label` < `writer_sense`**（label のほうが AI 寄りに読まれる）。名指しされた軸は
  達成目標であり、目標は均等に満たされる（則2）。ここが外れたら則2 の適用範囲を狭める必要がある。
- **`writer_sense_flat` は床。** writer_bio と同じ形なので、同じ結果になるはず。
- **`writer_sense` は、正直に言えば床である確率のほうが高い。** 22設計中の非ゼロは1つで、
  それも追試で消えた。この予測を書いておくのは、床だったときに「実は期待していなかった」と
  後付けしないためである。

### 何が起きたら「効いた」と言えるか

帰無対照（バイト同一の再判定）が既に1ペア動かす。したがって**対応ありペアで2〜3の移動は
何の証拠でもない。** `writer_human` が一度 6/1 を出して、それでもノイズと結論されている
（McNemar 両側 p = 0.125、増分の6割が1記事に集中）。同じ轍を踏まない。

そして**検出力が律速である**ことを先に認めておく。陽性対照
（`results/2026-07-31-mde-positive-control.json`）が測った最小検出可能効果は、
31ペアを独立とみなして **19.4ポイント**、正しい8記事クラスタで **29.0ポイント**。
**この装置は小さい効果を見られない。** 床だったという結果は「効果が無い」ではなく
「19〜29ポイント未満だった」としか読めない。

## 6. 撤退条件

先に書いておかないと、後から基準が動く。

- `--audit` の `emit_rate` が 0.6 を超えたら、**生成を回さずに**設計を直す（writer_bio 化）。
- `writer_sense` と `writer_sense_flat` が区別できなければ、希少性の機構は飾りである。
  そのときこの設計の中心的な主張は外れており、五感・喜怒哀楽そのものの評価に切り替える。
- `writer_sense` が帰無対照の床（移動1〜2ペア）に収まったら、**打ち切る。**
  閾値・語彙プール・歩幅をいじって再挑戦しない。それは則3 が禁じている探索（効かなかった
  次元の中で係数を探す）そのもので、このベンチはそれで22設計を使い切っている。

## 7. 実行

```bash
# 0. 生成前に、均等充足していないことを確認する（無料）
python affect_state.py --audit 2000
python affect_state.py --seed 7 --preview     # 引きを目で見る

# 1. 基準と3アーム。--seed を明示しないと乱数が引かれて印字・記録される
python hidden_check.py --live --seed 20260807 \
  --arms writer_agent,writer_sense,writer_sense_flat,writer_sense_label \
  --topics 8 --checkpoint /tmp/sense.jsonl --json-out results/YYYY-MM-DD-affect-seed.json

# 2. 帰無対照を作る。変異ではなく、同じ本文をアーム名だけ変えて複製したもの
#    （2026-07-31-mutation-null-control.json がこの形。これ抜きの数値は読めない）
python - <<'PY'
import json, pathlib
src = json.loads(pathlib.Path("results/YYYY-MM-DD-affect-seed.json").read_text())
src["arms"] = {"writer_sense_null": src["arms"]["writer_sense"]}
pathlib.Path("/tmp/sense-null.json").write_text(json.dumps(src, ensure_ascii=False))
PY

# 3. 判別。--run は繰り返せて、全 run が同じ対戦相手に当たる
#    （トピックあたり4本 = 31ペア・両順序 = 62試行/条件。対応ありペアは自動で出る）
python discriminate.py --corpus /tmp/human_corpus --opponents 4 \
  --run results/YYYY-MM-DD-affect-seed.json --run /tmp/sense-null.json \
  --json-out results/YYYY-MM-DD-affect-seed-discrimination.json
```

台帳の sha1 が違う実行同士は writer 系を比較できない（C-1）。**シードも同じ性質を持つ**ので、
`hidden_check.py` は `--seed` を省略しても引いた値を印字し、結果 JSON の `"seed"` に記録する。

## 8. rig 本体との関係

`skills/engine/recipes/de-ai-smell` は**書かれた後の散文から AI 臭を落とす**レビュー機構で、
これはそれとは別の層にある。両者の住み分けを明示しておく。

| | de-ai-smell | writer_sense |
|---|---|---|
| 層 | 校正（生成後） | 素材供給（生成前） |
| 機構 | 徴候カタログで指摘し書き直す | 状態を渡して、使うか捨てるかは委ねる |
| 則2 の射程 | 内側（指摘は検査可能な要求である） | 外側（満たすべき対象が無い） |

de-ai-smell 自身が注意書きに「機械が文を平準化するのも一種の AI 臭」と書いており、
このベンチの実測はそれを裏づけている（`riglint` が lint を改善しながら判定を悪化させた）。
**de-ai-smell はレビュー道具として有用であり、人間らしさを作る機構ではない。** ここで測るのは後者。
