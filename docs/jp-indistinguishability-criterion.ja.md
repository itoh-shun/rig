# 「人間が書いた文章と相違ない」を、合否の出る基準にする

受入基準を1つに決めるためのメモ。実装は `indistinguishable.py`、テストは
`tests/test_indistinguishable.py`。

目標を「最終的に人間が書いた文章と相違なければいい」と置いたとき、この装置で
**その基準が何点なのか**と、**どういう検定なら「相違ない」と言えるのか**を確定させる。
結論を先に書くと、直感的な答えは2つとも間違っている。

---

## 1. 目標は 50% ではない — 実測は 69.4%

「人間と相違ない ＝ 判定役が当てずっぽうになる ＝ 50%」と考えたくなる。**この装置では違う。**

陽性対照（`results/2026-07-31-mde-positive-control.json`）は、アームの記事に実在の人間記事を
段階的に混ぜて判定し直している。

```
人間テキストの混入率      判別率
  0.00（アーム単体）      98.4%   61/62
  0.125                 98.4%   61/62
  0.25                  88.7%   55/62
  0.50                  79.0%   49/62
  0.75                  74.2%   46/62
  1.00（全文が人間）      69.4%   43/62   ← 床
  帰無（バイト同一）      100.0%   62/62
```

**混入率 1.00 では候補そのものが人間の記事である。それでも 69.4% で当てられる。**

したがって:

> この装置における「人間と相違ない」は **69.4%** であって 50% ではない。

これは実務的に効く。判別率 70% のアームは「人間まであと 20 ポイント」ではなく、**床にいる**。
50% を目指した最適化は、**人間の文章ですら到達しない数値**を目指すことになる。

（なぜ床が 69.4% なのかは別問題として残る。強制二択・両順序で、判定役は必ずどちらかを選ぶ。
人間記事どうしを当てさせる human-human 条件も 69.4% だった。指標の性質であって、
テキストの性質ではない。）

---

## 2. 差分検定では「相違ない」を示せない

このベンチのこれまでの比較は全部**差分検定**である — 基準に対して動いたか。
差分検定が棄却に失敗しても、それは同等の証拠にならない。**とくにここでは危ない。**

MDE は 31ペアを独立とみなして 19.4 ポイント、正しい8記事クラスタで 29.0 ポイント。
**検出力が無いのだから、差分検定はほぼ構造的に「有意差なし」を返す。**
それを「人間と相違ない」と読むのが、このプロジェクトで最も高くつく誤読になる。

正しい道具は**同等性検定（TOST）**で、「床と違うか」ではなく「床から一定のマージン以内か」を
問う。そして差分検定が隠してしまう3つ目の答えを持つ。

| 判定 | 意味 |
|---|---|
| `EQUIVALENT` | マージン内で人間と同等と**言える** |
| `DIFFERENT` | マージンを超えて人間と**異なる** |
| `UNDERPOWERED` | **どちらとも言えない**（差分検定なら「有意差なし」と出る領域） |

`indistinguishable.py` の終了コードは `EQUIVALENT` のときだけ 0 になる。
**`UNDERPOWERED` は合格ではない。** その混同を防ぐためだけに、このスクリプトは在る。

単位は topic（8クラスタ）。結果ファイル自身が
`"primary_unit": "topic/generated article (8 clusters)"`、
`"secondary_units": [..., "trial/order (62; anti-conservative)"]` と宣言している。
62試行を独立として扱うと区間はおよそ半分になり、有意性が製造される。
bootstrap は**トピックを**リサンプルする。

## 3. 現状（マージン ±10 ポイント・topic 8クラスタ）

```
アーム              判別率    床との差    90% CI            判定
writer_agent        98.4%    +30.7    [+14.1, +49.0]    DIFFERENT
pc_human_0250       89.1%    +21.3    [ +7.8, +38.0]    UNDERPOWERED
pc_human_0500       77.6%     +9.9    [ -0.5, +19.8]    UNDERPOWERED
pc_human_0750       72.4%     +4.7    [ -1.6, +10.9]    UNDERPOWERED
pc_human_1000       67.7%     +0.0    [ +0.0,  +0.0]    EQUIVALENT（自己一致）
```

読むべきは3行目と4行目である。

> **本文の 75% が実在の人間の散文であっても、8クラスタでは「人間と同等」を示せない。**

テキストが足りないからではない。**測定器が解像できない**からで、同等を示すには topic が
約12必要になる（現在8）。50% 混入にいたっては点推定 9.9 がマージン 10.0 のすぐ内側に
あるため必要クラスタ数が発散し、実質到達不能になる。

そして `writer_agent` は点推定が既にマージンの外なので、**トピックをいくら増やしても
同等にはならない。** 必要なのはデータではなくアームの改善で、この2つを混同すると
固定された差に対してデータを集め続けることになる。

## 4. だからどうするか

受入基準としてはこう置く。

```bash
python indistinguishable.py --run <discriminate の出力> --arm <アーム> \
    --floor-arm pc_human_1000 --margin 0.10
# exit 0 = EQUIVALENT のときだけ合格
```

そのうえで、目標達成には**2つの独立した条件**が要る。片方だけでは足りない。

1. **アーム側** — 点推定を床＋マージンの内側へ入れる。現状 +30.7 ポイント。
   MDE が 19.4〜29.0 なので、**残り距離のほぼ全部が1 MDE 分**である。
   つまり「効いたかどうか分かる介入」は、ほぼ「一発で全部詰める介入」に限られる。
   小さな改善を積む戦略は、この装置では**見えないまま積むことになる**。
2. **測定器側** — topic を 8 から 12 以上へ増やす。生成コストはかかるが台帳は共有できる。
   `docs/jp-naturalness-engineering.ja.md` §2 が既に「1条件あたり約150試行が要る」と
   書いており、トピック数の拡張はそこでも挙がっている未着手項目である。

**2 を先にやるほうが安い。** 1 を試しても、いまの解像度では成否が判定できない。

---

## 5. この基準の限界

- **床 69.4% は1回の陽性対照から来ている。** その測定自体の分散は測っていない。
  床が実は 65% や 75% なら、マージンの意味が変わる。床の反復測定は未実施。
- **マージン ±10 ポイントは選択であって導出ではない。** 何ポイント以内なら「相違ない」と
  みなすかは、最終的に用途が決める。狭くすれば到達不能になり、広げれば基準が緩む。
- **8クラスタの bootstrap は信頼区間としては粗い。** 少数クラスタの percentile bootstrap は
  被覆が名目より低くなりやすく、**同等性の側に甘い**方向へ倒れうる。クラスタが増えたら
  効果の推定と一緒にここも見直す。
- **強制二択という形式自体が床を作っている。** 判定役に「どちらか選べ」と言う限り 50% には
  ならない。別形式（単独提示での人間/AI 二値判定、あるいは信頼度つき）にすれば床は動くが、
  それは指標の変更なので、過去の全結果と比較できなくなる。
  **指標を動かしながら設計を比べるのは、このベンチが最も高くついた教訓**なので、
  変えるなら全アームを取り直す覚悟が要る。
