`asyncio.gather` と `asyncio.wait` は「複数の待機可能オブジェクトをまとめて待つ」点は同じですが、**返すもの・例外の扱い・キャンセルの伝播**がまったく違います。

## 要点の比較

| | `gather` | `wait` |
|---|---|---|
| 戻り値 | 結果の **リスト**（引数の順序どおり） | `(done, pending)` の **set 2つ**（順序なし） |
| 結果の取り出し | そのまま使える | 自分で `task.result()` を呼ぶ |
| 例外 | 呼び出し側に**送出される**（`return_exceptions=False` の既定時） | **送出されない**。Task の中に保持されたまま |
| 部分的な完了 | 不可（全部終わるまで待つ） | `return_when` で「最初の1つ」「最初の例外」で打ち切れる |
| タイムアウト | 引数なし（`asyncio.timeout` 等と組み合わせる） | `timeout=` あり |
| コルーチンの受け入れ | OK（自動的に Task 化） | **Python 3.11 で不可**（Task/Future のみ） |

## gather

```python
results = await asyncio.gather(fetch(1), fetch(2), fetch(3))
# results == [結果1, 結果2, 結果3]  ← 引数の順序が保証される
```

- `return_exceptions=True` にすると、例外は送出されずに結果リストの中へ例外オブジェクトとして入ります。全件の成否を取りたいときはこちら。
- **落とし穴**: `return_exceptions=False` で子の1つが例外を投げると、その例外は即座に呼び出し側へ上がりますが、**残りのタスクはキャンセルされず走り続けます**。放置すると "Task exception was never retrieved" 警告やリークの原因になります。
- 一方、`gather` が返す Future 自体をキャンセルすると、未完了の子は全部キャンセルされます。

## wait

```python
tasks = [asyncio.create_task(fetch(i)) for i in range(3)]
done, pending = await asyncio.wait(tasks, timeout=5,
                                   return_when=asyncio.FIRST_COMPLETED)
for t in done:
    print(t.result())      # ここで初めて例外が上がる可能性がある
for t in pending:
    t.cancel()             # タイムアウトしても wait は自動でキャンセルしない
```

- `return_when` は `ALL_COMPLETED`（既定）/ `FIRST_COMPLETED` / `FIRST_EXCEPTION`。
- タイムアウトしても**未完了タスクはキャンセルされません**。後始末は自分の責任です。
- `wait` は例外を絶対に投げないので（`TimeoutError` すら投げません）、「どれが失敗したか」を自分で調べる制御的な用途向けです。

## 使い分け

- **全部成功させたい / 結果を順番どおりに使いたい** → `gather`
- **どれか1つ終わったら先へ進みたい、タイムアウトで打ち切りたい、各タスクの成否を個別に見たい** → `wait`
- **Python 3.11 以降で、1つ失敗したら兄弟も確実にキャンセルしたい** → `asyncio.TaskGroup` が第一選択です。`gather` の「残りが走り続ける」問題が構造的に解決されています。

```python
async with asyncio.TaskGroup() as tg:
    t1 = tg.create_task(fetch(1))
    t2 = tg.create_task(fetch(2))
# 抜けた時点で両方完了。どちらかが失敗すれば他方はキャンセルされ、
# ExceptionGroup として送出される
```

- **終わった順に処理したい** → `asyncio.as_completed`
- **タイムアウトだけ付けたい** → `async with asyncio.timeout(5): await asyncio.gather(...)`（3.11+）

ざっくり言えば、`gather` は「まとめて1つの処理として扱う高レベル API」、`wait` は「個々のタスクの状態を自分で管理する低レベル API」です。

## 結論から

- **`asyncio.gather`** … 「全部の結果を、渡した順番でまとめて受け取る」ための高レベル API
- **`asyncio.wait`** … 「Task 群の完了を待つ」だけの低レベル API。結果の取り出しは自分でやる

## 主な違い

| | `gather` | `wait` |
|---|---|---|
| 戻り値 | 結果の `list`（**引数の順序どおり**） | `(done, pending)` の **`set`**（順序なし、中身は Task） |
| 結果の取得 | そのまま値が返る | `task.result()` を自分で呼ぶ |
| 例外 | 既定で**呼び出し元に即 raise** | **raise しない**。Task の中に保持される |
| 部分的な待機 | 不可（常に全件） | `return_when=FIRST_COMPLETED` などで可 |
| タイムアウト | なし（`wait_for` / `asyncio.timeout` で包む） | `timeout=` 引数あり |
| コルーチンを直接渡す | OK（自動で Task 化） | **Python 3.11 以降は TypeError**。`create_task` で包む必要あり |
| キャンセル伝播 | gather 自体を cancel すると子も全部 cancel | タイムアウトしても **pending の Task は走り続ける**（自分で cancel する） |

## コード上のイメージ

```python
# gather: 順序保証つきで値がそのまま返る
r1, r2, r3 = await asyncio.gather(f(1), f(2), f(3))

# wait: Task を作って渡し、結果は自分で取り出す
tasks = [asyncio.create_task(f(i)) for i in range(3)]
done, pending = await asyncio.wait(tasks, timeout=5)
results = [t.result() for t in done]   # 順序はバラバラ
for t in pending:
    t.cancel()                          # 自分で後始末が必要
```

## ハマりどころ 2 つ

**1. `gather` は例外が出ても他のタスクを止めない**

既定（`return_exceptions=False`）では最初の例外が即座に呼び出し元へ伝わりますが、残りのタスクは**キャンセルされずバックグラウンドで走り続けます**。「誰も待っていない Task」が残るのが典型的なリーク源です。`return_exceptions=True` にすると例外オブジェクトが結果リストの要素として返り、全件の完了を待てます。

**2. `wait` は await しても例外を投げない**

`await asyncio.wait(...)` は Task が例外で終わっても静かに返ります。`t.result()` を呼ぶか `t.exception()` を見るまで失敗に気づけないので、例外の握りつぶしが起きやすいです。

## 使い分けの指針

- **全部の結果が順番どおり欲しい** → `gather`
- **「どれか 1 つ終わったら先に進む」「タイムアウトつきで待って、残りを個別に処理したい」** → `wait`
- **終わった順に逐次処理したい** → `asyncio.as_completed`
- **Python 3.11 以降で新しく書くなら** → `asyncio.TaskGroup` を第一候補に。子タスクの失敗時に兄弟を自動キャンセルし、スコープを抜けるまで必ず待つ（structured concurrency）ので、上記のハマりどころ 1 が構造的に起きません。

```python
async with asyncio.TaskGroup() as tg:
    t1 = tg.create_task(f(1))
    t2 = tg.create_task(f(2))
# ここを抜けた時点で両方完了。どちらかが失敗すれば ExceptionGroup が送出される
print(t1.result(), t2.result())
```

`wait` は「低レベルの待機プリミティブが本当に必要なとき」に残す、くらいの位置づけで十分です。
