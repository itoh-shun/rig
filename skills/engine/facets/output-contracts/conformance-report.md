# output-contract: conformance-report

ガバナンス監査人（`governance-auditor`）の出力構造。組織の品質ガバナンスを「届いているか・効いているか・消せないか」で採点し、乖離を機械抽出できる固定フォーマットで出す。前置き・挨拶は禁止。

### 形式

```
## rig govern: ガバナンス適合性

対象: <org[/team]・プロジェクト N 件の1行サマリ>
総合: <適合 | 乖離あり | 未統治>  ｜ 適合率 <NN>%  ｜ 乖離 <M> 件（重大:<a> / 中:<b>）  ｜ force 率 <NN>%  ｜ 読めなかった記録 <K> 件  ｜ runs 未列挙 <U> 件（<project 名>）

### 層の到達
| 層 | 文書 | 到達 | 備考 |
|---|---|---|---|
| org | <id@version> | <N/M プロジェクト> | <未到達のプロジェクト名 or —> |
| team | <id@version> | <N/M> | <—> |
| project | <id or 無し> | <N/M> | <—> |

### チーム別
| team | projects | 適合率 | force 率 | 読めなかった記録 | 落ちている検査 |
|---|---|---|---|---|---|
| <team-a> | <N> | <NN>% | <NN>% | <K 件 or —> | <check id 列 or —> |

### 乖離（重い順・各に手）
#### [G1] <断定形の見出し（例: team-c の3リポジトリに org ポリシーが届いていない）>
- 概念: <policy | permission | approval | waiver | ledger>  ｜ 深刻度: <重大|中|低>
- 根拠: <確認した具体箇所（ファイル・check id・数値）>
- 手: <ポリシーを直す / 権限を配り直す / 基準を現実に合わせる / 例外をポリシーへ昇格 のどれか＋具体策>

#### [G2] ...

### 最優先の1手
- <全部はやらない前提で、まず打つべき1手を名指し（多くは「org 層を届かせる」か「台帳の検証を通す」）>
```

### ルール

- **総合行**（適合/乖離あり/未統治・適合率・乖離件数・force 率）を先頭付近に必ず出す（機械抽出の入口）。**force 率は総合行に必ず入れる**（この層で最も情報量が多い1数字）。
- **数字は `rig-wb govern conformance --json` / `rollup --json` の実測から取る**。推定値を書かない。計測できなかった指標は `未計測` と明記する（0% と書かない）。
- **読めなかった task record の件数を適合率に必ず並べる**。`--json` の `task_records.unreadable`（rollup では `unreadable_task_records`）が空でなければ、総合行と該当チーム行に件数を出す。**不適合として数えない**（読めないことは違反の証拠ではない）**が、黙って分母から落とさない**——「55件中52件から出した適合率」が「適合率」として出た時点で、この報告は最も気づかれにくい形で誤っている。`task_records` が `null` の報告は「まだ runs を読んでいない」であって「全件読めた」ではない。
- **runs ディレクトリ自体を列挙できなかったプロジェクトは、件数と別枠で名指しする**。rollup の
  `unlisted_runs_directories` が空でなければ、総合行に「runs 未列挙 <N> 件（<project 名>）」を出す。
  **読めなかった記録の件数に足し込まない**——列挙できなかったディレクトリに記録が何件あるかは
  誰も測っていないので、足した時点で未計測の数字を件数として出したことになる。このプロジェクトは
  run 由来の検査（`required_criteria` / `approvals` / `force_rate`）が0件に対して通っているため
  適合率が高く出る。**適合として扱わない**が、**適合率から黙って外しもしない**（外せば「測れた
  プロジェクトだけの適合率」が「適合率」として出る）。
- **`acceptance.json` が読めなかった accepted run も名指しする**。`required_criteria` の detail に
  「未走査」として出る。`task_records.unreadable`（＝`task.json`）とは別のファイルなので、
  そちらが空でもこちらは空とは限らない。
- **org 層が届いていない場合、総合を「未統治」にする**。ローカル基準に対する自己採点を適合とは呼ばない。
- 乖離は `[G<n>]` で採番し、**断定形**の見出し。`概念 / 深刻度 / 根拠 / 手` を必ず埋める。
- **手は4種のいずれかに寄せる**（ポリシー改定・権限再配分・基準の現実化・例外の昇格）。**quorum を上げる提案は原則しない**（効くのは職務分離と鮮度）。
- **「ある」と「効いている」を区別**：ポリシー文書が存在するだけで conformance の数字が動いていないものは乖離として挙げる。
- **緩和を黙って勧めない**。基準が実務に合っていないと判断したら「ポリシー改定」として明示的に書く（例外の出し続けを提案しない）。
- read-only。ポリシー・権限・台帳を書き換えない（変更の実行は `rig-wb govern` の各コマンドと人間の判断へ委譲）。
