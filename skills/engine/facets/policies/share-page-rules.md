# policy: Share Page Rules v1

エージェントが作った成果物を、ほかの人やスマホの自分が読む **1 枚の HTML** にするための
規則です。公開先は Claude の Artifact です。前半は公開できる形の条件、後半は読める中身の
条件です。前半は `rig-wb share-check` が機械で見ます。後半は reviewer が見ます。

## 1 枚で完結させる

1. **出力は `share/<slug>.html` の 1 ファイルだけです。** 公開するのはこの 1 枚なので、
   別の CSS・JS・画像を読むと、公開した先で壊れます。CSS と小さな SVG は `<style>` と
   インラインで書き、画像とフォントは `data:` URI で埋め込みます。
2. **外部から読んでよいのは次だけです。** script は cdnjs.cloudflare.com、
   cdn.jsdelivr.net（npm 配下）、unpkg.com、cdn.tailwindcss.com、code.jquery.com。
   stylesheet は Google Fonts。これは Artifact のページ契約が許す範囲で、それ以外は
   閲覧時に読み込まれません。既定は外部ゼロで書きます。
3. **大きさは 16 MB 以下、目安は 1 MB 以下です。** 減らすときは、画像の解像度より先に枚数を
   減らします。読ませる画像は全幅のまま残します。

## どの画面でも読めるようにする

1. `<title>` は 2〜4 語の名前にします。一覧で似たページと見分けられる範囲を先頭に置き、
   ファイル名にも同じ範囲を入れます。説明は title に詰めず、公開時の description へ回します。
2. **`<title>` と `<style>` から書き始めます。** Artifact は公開時に doctype、`<head>`、
   viewport、スマホの safe-area の余白を外から被せます。`<html>`・`<head>`・`<body>` を
   自分で書かず、`:root` の padding を上書きしません。`<title>` は先頭 8 KB の中に置きます。
3. 色はすべて `:root` のトークンで定義し、本文では値を直接書きません。ダークモードは
   `@media (prefers-color-scheme: dark)` の中で `:root:not([data-theme="light"])` に、
   さらに `:root[data-theme="dark"]` にも同じトークンを定義し直します。`body` には
   背景色を明示します。埋め込み先の背景が透けると、文字が沈みます。ライトの値は素の
   `:root` で一度ずつ定義し、ダークの 2 か所では定義し直すだけにします。
4. 本文の幅は 940px 前後を上限にし、左右に 16px の余白を外側の要素 1 つで取ります
   （上下は `padding-block` で書き、左右を 0 にする shorthand を使いません）。390px 幅で
   横スクロールを出しません。横に広い表・図・コードは、それぞれ `overflow-x: auto` の
   入れ物に入れます。表に `min-width` を付けず、狭い画面では行ごとのカードに畳みます。文字を
   縮めて押し込みません。
5. 見出しは h1 を 1 つ、段を飛ばさずに並べます。画像には中身を言う `alt` を付けます。
   リンクの文言は行き先が分かるものにします。

## 読む人のために書く

1. **材料に無い事実を足しません。** 空いた節を埋めるために数字や日付を作りません。節ごと
   消します。推測を書くときは推測だと書き、図では破線にします。
2. **主題にいちばん紙面を割きます。** 背景や経緯に図を 3 つ使い、本題を箇条書き 1 枚で
   済ませる、という配分にしません。
3. **同じ一覧を 2 回読ませません。** 節で 1 件ずつ説明するなら、冒頭の一覧表から外します。
   最後に同じ一覧のまとめを置きません。
4. **読み手に解読させる記号を作りません。** 3 色以上の色分け、`S1`/`A` のような抽象的な
   符号、同じ数字の単位違いの言い直し。事実ごとに書き方を 1 つに決めます。
5. **日付には曜日を付けます。** 曜日は手で書かず、コードで計算します。範囲は両端に付けます。
6. **数字は、系列の少ないグラフと、要点だけの短い表（5 行前後）で見せます。**
7. **日程・手順・構造は図にします。** 図は SVG を `viewBox` 付きでインラインに書き、色は
   ページのトークンだけを使います。構造図には、誰の持ち物かを分ける境界線と、矢印ごとの
   ラベルを付けます。表で済むものを図にしません。
8. **本文は言い切りで書きます。** 話し言葉や問いかけの見出しにしません。

## 出してはいけないもの

1. **秘密情報。** API キー、トークン、パスワード、社内 URL、IP の許可リスト。センサーは
   名前つきのパターンだけを捕ります。捕れないものは reviewer が見ます。
2. **明示の許可が無い個人情報・顧客名・社外秘の識別子。** 材料に入っていても、ページに
   載せてよいとは限りません。迷ったら載せずに、本人に聞きます。
3. **本物の組織や人物を装うもの。** ロゴ、署名、ドメインを借りたページ、本物に見える
   領収書や評価、入力を集めるフォーム。センサーは外部へ送信するフォームと
   `meta refresh` を落とします。
4. **本人が決めていないこと。** 本人の約束、ほかの人への依頼、まだ決めていない判断を、
   ほかの人が読むページに書きません。

## 公開について

Artifact は作成時には非公開で、共有するかどうかは本人が決めます。公開は gate を通った
ページだけに行い、同じファイルを直したときは同じ URL へ上書きします。

`noindex` や推測されにくい URL は、見つかりにくくするだけです。アクセス制御の代わりに
しません。
