# policy: independent-verification

## facet: policy / independent-verification

検証（受け入れ照合・採点・レビュー判定）の**担い手**に関するポリシー。プロンプト末尾への注入を前提とする。

> 原則：**採点者は生成者と別人**。成果物を作った agent に、その成果物の合否を判定させない。

### なぜ

エージェントに自分の出力を採点させると、**甘く付ける**（self-grading bias / self-praise）。生成直後は自分の意図が頭に残っていて、行間を補完して読んでしまうからだ。読者（次の gate）にはその文脈が無い。実例：de-ai-smell で自分の記事を自己採点して 41/50「合格」と付けたが、別の目に見せたら一発で「AI 臭い」＝23/50 相当だった。18点の過大評価は、生成者が採点したことが原因。

### ルール

1. **gate の照合は、生成した step とは別の subagent に dispatch する**。親（オーケストレータ）は照合を生成者にやらせず、独立 reviewer/checker を立て、その verdict 行だけを読む（context-minimal と同経路）。
2. **同一ターンで「生成 → 自分で合格判定」する経路を禁止**。acceptance-gate / review-gate / goal-loop の照合 / 生成系コンテンツrecipeの検閲は、すべて生成と別の担い手で行う。
3. **完全な独立が取れない小規模の場合**は、最低限の近似として「**コンテキストを変える**」— 再アンカー後に別ロールとして読む／音読する／一拍置く。ただし「生成直後に同一ロールのまま自己合格」は近似としても不可。
4. **疑わしきは不合格側に倒す**（生成者バイアスの逆張り）。独立検証者は「通す理由」でなく「落とす理由」を探す姿勢で読む。

### 測定器そのものにも適用する

原則の適用先は判定の**担い手**だけではない。**判定を下す道具**にも同じ規律が要る。

drill の採点器は、レビュアーの品質を測る道具である。その採点器のテストは採点器を書いた本人が書いたもので、
攻撃を想定したものは1形しか無かった。結果として、**「このコードはすべて正常である」と述べるだけの1段落が、
出荷済みの全ケースで 4〜5/5 を取る**状態が、コーパスの出荷時からずっと残っていた（2026-09-06 実測）。
バグではなく、役割の欠落である。物差しを壊す担当が誰もいなかった。

5. **採点規則・ゲートセンサーなど「合否を機械で決める仕組み」を変えたら、
   その仕組みを書いていない主体に攻撃集合を作らせる。** 依頼は「テストを通せ」ではなく
   「**欠陥を1つも見つけずに高得点を取る入力を作れ**」。実際に走らせて数字を出させる。
6. **成立した攻撃はそのまま回帰テストにする。** 閉じられなかったものは、
   **現在値を固定するテスト**として残す（黙って良くならない・黙って悪くならないため）。
   閉じない理由と、閉じるのに何が要るかをテストの docstring に書く。
7. **既存テストが green であることを保証と読まない。** 生成者が書いたテストは、
   生成者が思いつかなかった攻撃を含まない。これは (1) の系である——
   テストもまた生成物であり、その十分性の判定を生成者にさせてはならない。

実例（2026-09-06）：この規律に従って独立した主体に攻撃を書かせたところ、
所見単位に作り替えた直後の採点器に対して4件の攻撃が返り、3件が成立した。
うち1件は「**契約に正しく従うと減点される**」——証拠アンカーを契約どおり書いた所見が 0 点、
書かなかった所見が 1 点になっていた。契約を壊す方向に人格を鍛える採点器だった。
自分では見つけられなかった種類の欠陥である。

### 適用範囲

- `patterns/acceptance-gate`・`patterns/review-gate`：照合・レビューは生成 step と別 persona/subagent。
- `recipes/goal-loop`：⑤照合（verification）を生成（④委譲先）と切り離す。
- 生成系コンテンツrecipe：採点・検閲は書き手と別。**書いた本人の自己スコアを最終判定にしない**。
- **`/rig:drill` の採点器（`rig_workbench/workbench/detection_corpus.py`）と受け入れゲートのセンサー**：
  規則を変えたら独立した攻撃集合を作らせる（上記 5〜7）。`scorer_version` を上げ、
  版が違う行の率を並べない。

### 禁止事項

- 生成者に自分の成果物の最終合否を出させない。
- 自己採点の高得点を「合格」の根拠に使わない（参考値に留める）。
