# policy: Design Constraint Rules v1

プロジェクト固有のデザイン制約——使ってよい値、使ってよいコンポーネント、書いてはいけない
表現——を、**宣言したまま守られない状態にしない**ための規則です。対象は `/rig:design` が
作る成果物（デザイン仕様書・コンポーネント仕様・実装画面のスナップショット）です。

一般原則のカタログ（`[[ui-ux-heuristics]]`・`[[a11y-wcag]]`）は「どの画面にも効く良し悪し」を
持ちます。この policy が扱うのはその逆で、**このプロジェクトでだけ真である取り決め**です。

## 宣言する

1. 制約は **`<repo>/.claude/design-constraints.json`** に、機械可読な形で置きます。
   スキーマは `manifests/design-constraints.schema.json`、雛形は
   `manifests/design-constraints.template.json` です。
2. **値はプロジェクトが所有します。** rig は雛形とスキーマだけを出荷し、パレットも
   コンポーネント名も持ち込みません。埋めるのは、そのプロジェクトのデザイナーです。
3. 雛形に **`[要記入]` が1つでも残っている間、センサーは未検査を返します。** 置いただけの
   雛形から合格は取れません。宣言と実体が食い違ったまま緑になる経路を残さないためです。
4. 状態は3つあり、**どれも合格ではありません**。区別を潰さないでください。

   | 状態 | 意味 |
   |---|---|
   | `checked` | 宣言を読み、成果物と突き合わせた。違反の有無はこの状態でだけ言えます |
   | `unchecked` | **宣言はあるのに検査が成立しなかった**（`[要記入]` が残っている・JSON が壊れている・成果物が読めない） |
   | `not-configured` | そもそも宣言が無い。強制すべき制約が存在しない |

   `not-configured` は「宣言だけで守られていない」状態ではありません——宣言そのものが
   無いからです。ただし**黙って通してよいという意味でもありません。** 検査していないことを
   verdict に書きます。`unchecked` は宣言に反しているので、合格にしません。

## 成果物をセンサーに読める形で書く

検査できない書き方をすれば、制約は宣言に戻ります。成果物の側にも義務があります。

5. 値を書くときは**トークン名で参照します** — `token(<グループ>.<名前>)`、CSS では
   `var(--<グループ>-<名前>)`。生値を直接書いたものは、宣言集合に一致しない限り違反です。
6. デザイン仕様書には**「使用トークン」表**を置きます。本文の散文はセンサーに読めませんが、
   表は読めます。表に載っていない値を本文が使っていないかは、レビュアが突き合わせます。
7. コンポーネントは `<Button>` のように**名前で参照します**。インベントリに無い名前は違反です。

## センサーが主張してよい範囲

`scripts/check_design_constraints.py`（インストール済みなら `rig-wb design-constraints`）が
検出するのは次の4クラスだけです。これを
「制約遵守を検査した」と言い換えません。

| クラス | 内容 | 検出 |
|---|---|---|
| `raw-value` | 宣言トークンに解決しない色・長さ・フォントが成果物にある | ○ |
| `unknown-token` | 存在しないトークン名を参照している | ○ |
| `unknown-component` | インベントリに無いコンポーネントを参照している | ○ |
| `prohibited-expression` | 禁止表現が出現している | ○ |
| （トークン化されていない散文） | 「ブランドの青を使う」のように、値もトークン名も書かずに指示している | **×** |

**最後の1クラスは捕れません。** 構造的に検出クラスの外側です。これを捕れていることに
しません。実測値は `tests/fixtures/design-constraints/` の種で測り、報告に出します。捕れない
クラスは**レビュア判定**として明示します。「見ていない」を「合格」と取り違えない、という
`[[layout-fit-rules]]` と同じ区別を、環境ではなく**範囲**に適用したものです。

### どう読むか（実装が決めていることの明示）

- **全角と半角を同じ参照として読みます**（NFKC）。`token（color.brand）` は日本語 IME で
  日常的に起きます。ここを潰さないと、参照そのものが見えず、違反が「無い」のではなく
  **「検査されていない」**状態になります——最も危険な沈黙です。
- **禁止表現は本文全体に対して照合します**（行単位ではありません）。日本語の折り返しで
  「こちらを / クリック」と割れても、表示される成果物には禁止表現が出るためです。
  既定は大文字小文字を区別しません（`case_sensitive: true` で変えられます）。
  **`case_sensitive: true` が変えるのは大小の扱いだけで、他の正規化は同じように通ります**
  ——ここだけ生テキストに当てていたとき、ゼロ幅を1つ挟むだけでその規則だけがすり抜けました。
- **表示に現れない文字は、値・参照・禁止表現のすべてで落とします。** 判定には Unicode の
  `Default_Ignorable_Code_Point`（＝描画時に無視されるべきと **Unicode 自身が定めた**集合）を
  使います。ゼロ幅空白、ソフトハイフン（U+00AD）、異体字セレクタ（U+FE0F）、
  HANGUL FILLER（U+3164——カテゴリは `Lo`＝**文字**なのに描画されない）を含みます。

  ここは3回破られました。ゼロ幅5文字を**列挙**して U+00AD で、「カテゴリ `Cf`」に広げて
  U+3164 と U+FE0F で。**カテゴリ列挙も列挙です。** 「見えない」は自分で見立てるものでは
  なく、定義している側の集合を引くものです。

  **そして、ここが正規化の境界です。**「表示が同じか」は `unicodedata` から計算できません。
  `Default_Ignorable_Code_Point` は正しい表ですが、**表であることに変わりはありません**。
  この表の外にある方法（U+2800 BRAILLE PATTERN BLANK のように空白として描画される図形、
  フォント側の細工、画像化）で表示と字面を引き離した本文は、**検出クラスの外**です——
  「散文の『ブランドの青』」や「RLO の並べ替え」と同じ扱いで、レビュアが読む対象です。
  表に無い符号位置が見つかったら、符号位置を足したうえで**この段落を指してください**。
  機構を作り直す合図ではありません。

- **双方向制御は落としますが、並べ替えは元に戻しません。** RLO で表示上だけ禁止語に
  見える文章は検出しません。「落としている」と「無効化している」は違います——後者は
  主張しません。
- **結合文字は合成してから照合します**（NFD で分解された `café` も一致します）。
  正規化は行走査と禁止表現の照合で**同一の関数**を通ります。以前は片方が文字列全体、
  もう片方が1文字ずつで、正規化が2種類ありました。

  順序は **破棄 → 合成 → 照合** です。NFKC は**行ごとに、その行全体へ**当てます。

  ここは正規化の単位を賢くしようとして3周続けて破れました。1文字ずつでは NFD の
  `café` が合成できず、基底＋結合文字のまとまり単位にすると半角濁点 U+FF9E
  （正規化前は `Lm`、`Mn` になるのは NFKC の後）とハングルの jamo（`Lo`＝starter）が
  合流しませんでした。不可視文字を合成の**後**に捨てていたときは、`ﾀ` と `ﾞ` の間に
  U+200B を1つ挟むだけで——表示は変わらないのに——合成が壊れました。
  **単位を分けないのが答えです。** 行に切るのは行番号を残すためだけで、改行は合成にも
  分解にも関与しないので、行ごとの NFKC は本文全体の NFKC と一致します。

  これにより `fold(x) == fold(NFKC(x))` が**表に依存せず**成り立ちます。テストは
  手で選んだ文字列ではなく符号位置全域の乱択で確かめます——選んだ文字列は自分が
  直したケースの写しにしかならず、実際4周目はそれで「縛った」と書いてハングルで
  崩れました。**次の1文字ではなく、等式を守ってください。**
- **宣言された値から CSS プロパティを推測しません。** 宣言ファイルの値には
  プロパティ名が付いていないので、`Solid Grotesk`（実在の書体）と `2px solid red` は
  語彙では分けられません。分けようとした判別器は3代続けて実際の値に破れました——
  線種キーワード表は `Solid Grotesk` に、末尾語判定は `red 2px solid`（枠線ショート
  ハンドは順不同）に、語数の上限は `0 1px 2px black`（`box-shadow` の宣言）に。
  いずれも**宣言した値そのものが違反として上がる**方向で壊れています。

  なので推測をやめました。**長さを含む値の中の色語は、すべて色として宣言されます。**
  長さを含まない値（`Solid Grotesk`・`Black Han Sans`）は書体のままです。曖昧な値は
  書体としても登録されます。

  代償は `16px Display Black` のような書体指定が `#000000` も宣言することです。色の
  過剰宣言はその色のあらゆる使用を通してしまうので危険ですが、**黙って**起きなければ
  レビュアが裁けます——報告の `composite_declarations` に、どのトークンがどの値で何を
  宣言したかが載ります。過少宣言（宣言した影が違反として上がる）には同等の救済が
  ありません。この非対称が向きを決めています。

  **`制約 所見` を書くときは `composite_declarations` を読んでください。** 色のトークン
  でないものが色を宣言していたら、その色の使用は「宣言されているから通った」だけで
  意図されたものとは限りません。
- **コードフェンスの中も検査します。** 仕様書に貼られた実装断片も成果物です。
- **名前付き色とフォントは CSS 宣言の中でだけ読みます。** 散文の「エラーは red で示す」を
  生値として上げないためです。裏返せば、宣言の外に書かれた色名・書体名は読めません。
  プロパティ名はキャメルケースも同じものとして読み（`fontFamily` ＝ `font-family`）、
  HTML の `style="…"` 属性の中も宣言として読みます。その代わり、散文の中の
  `ログに "background: black" と出た` も宣言として読みます——**用法と言及を区別しないという
  規則どおり**で、判定はレビュアが行います（規則 8・9）。
- **宣言された値の中では、語単位の色名を長さがある値でだけ拾います。** `2px solid red` の
  `red` は拾い、`Black Han Sans, sans-serif` の `black` は拾いません——後者を拾うと、
  宣言した書体が消えて違反になり、誰も宣言していない黒が黙って通ります。
- **数字だけの3桁・4桁の16進は CSS 宣言の中でだけ色と見なします。** `fixes #123` の
  Issue 番号が色に化けるためです。6桁・8桁は散文でも拾います——使用トークン表の
  `| navy | #003366 |` を落とすほうが害が大きいからです。英字を含むもの（`#f00`・`#fff`）は
  色としか読めないので、桁数によらず拾います。
- **コンポーネント参照は JSX が書ける成果物でだけ見ます。** `.ts`・`.css` の型引数
  （`Map<String, Int>`・`<T,>(x) => x`）を要素と読み違えないためです。
- **宣言側の値も、成果物側と同じ正規化を通します。** 片側だけに当てると、宣言した値が
  そのまま違反として上がります（`{"surface": "white"}` が実際にそうなっていました）。
- **シンボリックリンクは辿らず、走査根の外は読みません。** 読めないディレクトリがあれば
  未検査にします——飛ばすと、中を一度も見ていないのに「違反 0 件」になります。
  拡張子・ドットディレクトリ・シンボリックリンクで外したものは、報告の `skipped` に残します。

### 測った再現率

**23/26**（`tests/fixtures/design-constraints/`、2026-09-07 実測）。偽陽性は正直な成果物
9件に対して **0件**、検出クラス外の散文3件も **0件**（＝宣言した境界が保たれている）。
採点は**行とクラスの完全一致のみ**で、値の部分一致による予備判定は置いていません——
置いていたときは、行番号の主張が守りになっていませんでした。

このコーパスは、ポリシーとスキーマだけを読み、**センサーを見ていない書き手**が作っています。
自分で書いた測定器を自分の答案で採点すると、何も測ったことになりません。

取りこぼした3件は、いずれも字句センサーの原理的な外側です。

| 取りこぼし | なぜ届かないか |
|---|---|
| 使用トークン表に書かれた生の書体名 | **書体名は値としての形を持ちません**（`#` も単位も無い）。CSS 宣言の外では、散文と区別できません |
| 16進色を文字列連結で分割 (`"#0A" + "84FF"`) | どの行にもその値が存在しません。式を評価しないと出てきません |
| 禁止表現を JSX のテキストと式に分割 | ソースに無く、**描画結果にだけ**現れます。センサーが読むのはソースです |

**`<button>` と小文字で書けばコンポーネント検査は回避できます**（参照構文は `<Capitalized>`）。
これは実装の欠陥ではなく、宣言した検出範囲そのものです。

**「違反 0 件」は「制約を守っている」ではなく「この4クラスでは見つからなかった」です。**
報告でこの2つを言い換えません。

- **NFKC は展開しかしません。** 合字 `ﬁ` を挟んだ `#ffﬁ000` は `#fffi000` に展開され、
  `#ffffff` として報告されます（元の文字列は色ではありません）。**隠す方向には働かない**
  ので再現率は落ちませんが、精度側にこの形の過剰報告が残ります。下の「用法と言及」と
  同じで、裁くのはレビュアです。

## 用法と言及を、センサーに判定させない

8. センサーは **use と mention を区別しません。** 「`#0A84FF` から移行した」という理由書きも、
   未一致の生値として位置つきで報告します。向きを読むのはセンサーの仕事ではありません。
9. **向きの判定はレビュアが行います。** センサーは再現率を、レビュアは適合率を担当します。
   この分担を崩して「センサーが賢く無視する」を足すと、無視すべきでないものを無視した時に
   誰も気づけなくなります。

## やらないこと

- **通すためにトークンを足しません。** 生値が落ちたら、まずそれが正しい値かを決めます。
  正しければトークンとして名前をつけて宣言し、違えば成果物を直します。順序を逆にしません。
- **禁止表現の一覧を、落ちたから削りません。** 外すなら、外したことと理由を報告に書きます。
- **`components` を空配列にして黙らせません。** 空配列は「1つも許可しない」の意味です。
  検査したくないならキーごと省き、省いたことを報告に書きます。
- **検出クラスの外にあるものを、あるように書きません。** 測った数字を、測った数字として
  報告します。捕れなかったものは、捕れなかったと書きます。

## 検査できないとき

次のいずれかのときは、**未検査として報告します。** 走らなかったことを合格として扱いません。
この区別が消えると、ゲートは何も守らなくなります。

- `[要記入]` が残っている（説明文 `_readme` の中の引用は数えません——制約は値の側です）
- JSON が壊れている、または **UTF-8 として読めない**
- **スキーマに無いキーがある。** `prohibited` を `prohibitted` と綴り間違えるだけで規則が
  丸ごと消え、`checked` / 違反 0 件で緑になっていました。知らないキーを黙って無視しません
- **`regex: true` の照合が制限時間（5 秒）を超えた、または成果物が上限（20 万字）を超えた。**
  破滅的バックトラックは1回の照合が返ってこないので、別プロセスに出して壁時計で打ち切ります。
  **返ってこないゲートは、通らないのではなく何も守っていません**
- シンボリックリンクを成果物として渡された、走査根の外を指していた、ディレクトリが読めない
- **JSON としては読めるが、スキーマに適合しない**（`version` が違う・`tokens` が空・
  値が文字列でない等）。ここを未検査にしないと、`tokens: {}` のファイルが
  「違反ゼロ」を返す経路が開きます
- 明示指定した制約ファイル（`--constraints <path>`）が存在しない——宣言が無いのではなく誤記です
- 成果物が読めない、検査対象のテキスト成果物が1件も無い

制約ファイルが既定パスに無いだけのときは `not-configured` で、これは未検査とは別です（規則 4）。
