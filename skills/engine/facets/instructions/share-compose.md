# instruction: share-compose

材料を 1 枚の HTML にまとめ、センサーを通す step です。規則は `share-page-rules`、
担い手は `share-composer` です。

## 手順

1. 材料と、読み手と、目的を確かめます。会話・指定されたファイル・作業結果から読みます。
   読み手が分からなければ、本人だけが読むページとして書きます。
2. 構成を決めます。主題、節の数、図にするもの、表にするものを先に決めます。
3. 雛形 `manifests/share-page.template.html` を `share/<slug>.html` へ複製します。slug は
   ページの範囲を表す英小文字とハイフンにします。既にある同じ slug のページを直すときは、
   そのファイルを上書きします。
4. 雛形は `<title>` と `<style>` から始まります。`<html>`・`<head>`・`<body>` を足しません。
   `{{...}}` をすべて埋めます。使わない部品は消します。雛形のスタイルは丸ごと残し、
   必要な部品だけを足します。新しい色を足すときは、ライトとダークの両方のトークンに
   定義します。
5. 画像やフォントを使うときは `data:` URI で埋め込みます。曜日は手で書かず、コードで
   計算します。
6. `rig-wb share-check --report .rig/share-check-report.json share` を実行し、報告を
   読みます。error をすべて直し、もう一度実行して `errors` が 0 であることを確かめます。
7. warning を読みます。直すものは直し、直さないものには理由を一行書きます。

## ガード

- 材料に無い事実、数字、日付、固有名詞を足しません。
- 正規表現の置換で HTML を書き換えません。入れ子のタグで途中が切れて、黙って壊れます。
  直すときは該当する要素を書き直します。
- センサーを通すために、規則に当たる部分を消して済ませません。消したなら、何を消したかを
  報告します。
- `share/` の外にページを書きません。センサーが見るのは `share/` だけです。
- 検査が走らなかったときは、通ったことにしません。未検査のまま次へ渡します。

## 出力の終端

この step の出力は、書いたページのパス、`share-check` の最後の 1 行、直さなかった warning と
その理由です。作業の説明や、次にやることの提案を添えません。
